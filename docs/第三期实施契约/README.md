## 1. 待维护者定

### 1.1 要拍板的四件事

**P-1 UDP 打洞是否进第三期**（04 块）。这是在改架构 §3.8 已拍板的"UDP 打洞修不修，第三期看中继回落率再定"。新事实：开源服务端从不在 UDP 上回 NAT 测试（`TestNatRequest`），控制端的 `udp_port` 永远是 0，UDP 打洞从来没运行过，所以回落率数据说明不了它值不值得修（笔记 05 §5，主会话已核对 `handle_udp`）。
- **推荐：进第三期，只修前置障碍、做普通 UDP 打洞**：服务端在 UDP 上回 NAT 测试（只回端口，限速）、接受 UDP 来的 `PunchHoleSent`（带防伪造随机数，UDP 上永不回包）、只对会回带随机数的 Porta 被控端转发 `udp_port`；Porta 控制端对自建服务器默认打开 UDP 打洞。服务端约 60 行加一个小模块，客户端 3 处挂钩各 2 行。UU 远程的日志里两端家宽都判为锥形 NAT（Cone），普通反射地址打洞大概率够用；端口预测、多端口这类重手段继续排最后。
- 备选：维持原决定，只在 §3.8 更正"现有数据里 UDP 打洞为零"。代价：开 TUN 的机器 IPv4 外网直连只能靠 IPv6。选这项时，04 块只保留 §4.4（开 TUN 时 IPv6 的验收和修法候选）和 §3.6（WebRTC/ICE 评估）；评估改在 03 块合入后做，对比对象换成局域网多候选和 IPv6 打洞。

**P-2 控制端的 TCP 和 UDP 从不同出口出去时**（03、04 块）。路由器透明代理只代理 TCP 时，控制端打洞请求的 TCP 来源 IP 和它的 UDP 注册 IP 不同：服务端误判"不在同一局域网"（03 块第 1 项要修的），UDP 打洞也必然失败（服务端把 TCP 来源 IP 和 UDP 映射端口拼成一个地址，04 §2.4）。
- **推荐 (3d)：两样都做**。代码：服务端用 `porta_from_id` 查发起方 UDP 注册 IP，和被控端的比，与现有 TCP 比较取"或"；为防伪造，这一路**只对 B 的主人、或在含 B 的共享地址簿上有任意权限的人生效**（个人簿不算：谁都能往自己的个人簿里加任意 ID）。这道门槛不算严：登录改绑只凭 uuid、会覆盖原主人，锁定后照样能改绑，所以实际门槛是"任一账号持有者 + 知道 B 的 uuid + 能伪造 UDP 源地址"（03 §2.1）。个人部署账号少、都是认识的人，接受这个门槛；"设备主人"这个身份的加固（已锁定设备的登录不再覆盖已有主人、命令行指定主人）按笔记 02 §2.6 的原计划放到第四期，和 Exit Node 一起做，第三期不改登录绑定。环境规则：开代理的网络里，到会合服务器的 TCP 也走直连（给 UDP 打洞用）。理由：UU 的日志证明局域网判定不该依赖 TCP 路径；IPv6 局域网候选也挂在同网判定上；维护者自己的设备都登录、都是主人，不用配规则就能走局域网。代价：新判定路径要查一次令牌和权限（只在 TCP 比较为否、UDP 比较为真时查，走主池，取连接最多等 3 秒，只影响这一条连接）；未登录的控制端用不上。
- (1) 只写环境规则，不做 03 块第 1 项：代码最少，但每个这样的网络都要手工配规则。
- (2a) 做 03 块第 1 项，直接比、不限权限：能伪造 UDP 源地址、知道 B 的 ID 的人，能骗出 B 的私网地址和一个只收一条连接、18 秒的监听（03 §2.1 有构造）。

**P-3 开 TUN 时 TCP 测出"对称 NAT"**（04 块；P-1 选"维持原决定"时这一项不用定）。TUN 会终结 TCP 再重新发起，源端口变了，现在用 TCP 测 NAT 类型的做法会误判成对称 NAT，任一端对称时被控端对 IPv4 直接走中继。UU 的日志显示 TUN 下 UDP 的反射地址就是家宽出口，UDP 打洞本身不受影响。
- **推荐 A：不测，试了再说**。服务端给了随机数、控制端有 `udp_port` 时，被控端不看 NAT 类型直接打洞（`rendezvous_mediator.rs` 一处 2 行），最多晚约 1 秒回落中继。
- B：用 UDP 向 21116 和 21115 各发一次 NAT 测试，比较映射端口。服务端要在 21115 多监听 UDP、防火墙多开一个端口，客户端再加两处挂钩。
- C：不改，开 TUN 的机器 IPv4 永远不做 UDP 打洞。

**P-4 局域网候选带不带 IPv6、带到什么范围**（03 块）。UU 的局域网直连实际大部分时间走以太网 IPv6，这是主路径。
- **推荐：ULA（`fd00::/8` 这类只在本地网络有效的地址）+ 和控制端某块物理网卡同一个 /64 前缀的全局地址**。限定"同一个 /64"后，威胁面和私网 IPv4 一样。排序上私网 IPv4 优先、全局 IPv6 优先于 ULA（控制端给 IPv6 候选晚 50~100 毫秒的先手），因为路由器的 ULA 前缀会变，而 Porta 没有会话中换路径。代价：上游 `src/server.rs` 改 1 条语句（双栈监听）、`libs/porta` 加 socket2 0.3。
- 只收 ULA：只下发全局前缀的家用网络里等于没做。改动面和推荐差不多，只省掉全局地址和按 /64 筛，双栈监听（`listen_dual`）和 `src/server.rs` 那条语句照样要。
- 不做：上游零改动，局域网里的全局 IPv6 仍可走现有 IPv6 打洞（要求服务端转发 IPv6、两端开 IPv6 打洞）。`select_candidates` 追加 IPv6、控制端收 IPv6 和按 /64 筛、`listen_dual`、`src/server.rs` 那条语句都没有。

不论选哪项，网卡枚举改双地址族、`Nic` 加 IPv6 字段、`has_gateway` 拆成 `has_gateway_v4`/`has_gateway_v6`、`is_physical` 参数改成 `IpAddr` 都要做：02 块测速的 `physical_snapshot` 和 04 §4.4 都要用，和 P-4 无关（03 §4.1 开头）。

## 6. 验收总览

在"路由器透明代理只代理 TCP + 本机开 TUN"的真实环境里做，具体步骤在 01、02、04 块的 §6.3 和 03 块 §6 的"端到端验收"。判"直连成功"一律看两样：

- 服务端 `conn_attempt`：`outcome` 是对应的直连值，`relay_req_count = 0`，并且同一 `b_id`、同一时间窗里没有 `signal = 'relay_only'` 的行（多出口代理下，回落的中继请求匹配不上会另记一行）。`direct_lan` 只说明被控端回了局域网地址，不代表连上了。
- 控制端日志：局域网看 `LAN candidate … won`、没有 `all N LAN candidates failed`；UDP、IPv6 看 `used to establish UDP connection with … punch`（`…` 是这一轮带上的传输，通常是 `UDP+TCP`）或 `used to establish IPv6 connection`，以及 `UDP NAT test to … finished: …, port=<非零>, …, success=true`（04 §6.3）。

另外：02 块要 2 台以上中继（只有一台时在同机另一个端口再起一个 hbbr）；03 块第 4 项要先在 Windows 测试机上同时装原版和 Porta，确认默认 ID 冲突真的会发生。
