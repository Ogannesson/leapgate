## 1. 目标与范围

被控端打开“允许作为出口”后，接受经过上游认证的出口登录，为控制端发来的每个目标解析域名、检查地址，再从物理网卡建立 TCP 连接。第一阶段只做 Windows。

多路复用隧道是一条远程会话里承载多个通道的端口转发；每个通道连接一个目标。控制端用 open 帧请求开通道，被控端用 opened 帧回答。哨兵是用于识别出口模式的特殊登录目标。CM 是被控端负责审批和显示连接的管理小窗。硬拒表示任何放行规则都打不开，软拒表示默认拒绝、主人可按网段放行。
fake-ip：mihomo 这类代理软件让系统 DNS 返回 198.18.0.0/15 的假地址，流量进它的虚拟网卡（TUN）再由代理软件转发；strict-route 是它强制流量都走 TUN 的选项。mux 即多路复用隧道。ICE 是第三期自研的直连打洞，STUN Binding 是它向会合服务器询问本机公网映射地址的请求，KCP 是 ICE 路径上的可靠传输。access-mode 是上游的“完全访问／仅共享屏幕／自定义”。

服务端目录不参与认证。出口关口通过后，仍按上游走设备密码或点击接受；开启 2FA 时，已信任设备只免 2FA，不免密码，不新增认证机制。

## 2. 用到的共用接口

直接使用 README §2 的常量和函数，不重复定义：

- `is_exit_target(host, port)` 只认精确的 `("leapgate-exit.invalid", 65536)`，大小写、末尾点和端口都不能变。
- `allowed()` 只有 Windows 且 Config `leapgate-allow-exit == "Y"` 时为真。登录、心跳、每个 open、每秒定时器共用它。
- `login_refusal(multiplex, secured)` 依次检查开关、多路复用、加密，返回 README §2.4 的固定登录错误。
- `Features.leapgate_exit = true` 表示构建支持出口，不代表开关开着或已经授权。
- ConnType 仍为 PORT_FORWARD。放行网段不进心跳。

被控端只在登录守卫、创建 mux 后两处用原始 `pf` 判哨兵。之后用 mux 的 `leapgate_exit: Option<String>` 判模式，其中字符串是控制端自报 ID，仅供日志，不作身份凭据。规范化只用于登录：`format!` 保留 i32 端口，得到 `leapgate-exit.invalid:65536`；摘要按 i32 四字节记录端口，CM 经 IPC 收到整串，均不截断。逐通道目标不进登录摘要，不能靠重新登录把普通转发改成出口。

## 3. 改动

### 3.1 `libs/leapgate/src/exit/policy.rs`：地址策略

本文件放纯函数，不访问网络、Config 或上游会话对象。以下是本块新增接口；内部结构字段可以按直接使用需要展开，不另建策略服务。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Reason {
    InvalidTarget, Reserved, Loopback, LinkLocal, Local, Lan,
    FakeIp, FakeIpLiteral, Nxdomain, ResolveFailed,
    NoRoute, Timeout, Refused, Unreachable,
}
pub struct AllowNets { /* cidr-utils 解析后的 IPv4/IPv6 网段 */ }
pub(crate) struct Snapshot { /* 全部本机地址、链路网段、本机公网 IPv4 */ }
pub fn parse_allow_nets(text: &str) -> Result<AllowNets, String>;
pub(crate) fn classify(
    ip: IpAddr, literal: bool, local: &Snapshot, allow: &AllowNets,
) -> Result<(), Reason>;
pub fn opened_message(reason: Reason) -> &'static str;
pub fn reason_code(reason: Reason) -> &'static str;
```

`reason_code` 精确返回 B12 的十四个小写下划线码。端口必须在 1~65535，主机不能为空，否则 `invalid_target`；不因端口用途拒绝 25 等合法端口。
放行语法为 CIDR 或单个 IP，按逗号、空白、换行分隔；空列表合法，单地址等价于 /32 或 /128。域名、带端口的字符串、非法前缀报错，不静默跳过。界面保存时拒绝整份非法输入；运行时遇到外部写坏的配置按空放行列表处理，不扩大权限。

现状：主 crate 根 `Cargo.toml:86` 声明 `cidr-utils = "0.5"`，锁定 0.5.11（`Cargo.lock:1185-1186`）。唯一的用法是 `src/server/connection.rs:27` 的 `use cidr_utils::cidr::IpCidr;` 和 `:1432` 的 `IpCidr::from_str(x).map_or(false, |y| y.contains(addr.ip()))`。`IpCidr::contains(IpAddr)` 遇到不同地址族恒为 false（`ip_cidr.rs:92-103`），正好满足“内嵌 IPv4 只按 IPv4 规则匹配”。其 `from_str` 比本节语法宽：`10` 得 10.0.0.0/8，`192.168` 得 /16（`ipv4_cidr.rs:18-20`、`:113-171`）；接受 `10.0.0.0/255.0.0.0` 等掩码写法；主机位静默清零（`:73-86`）。所以 `parse_allow_nets` 每项先按第一个 `/` 拆开：

1. 地址部分必须能用 `parse::<IpAddr>()` 解析（std 的严格写法）。
2. 前缀部分必须是纯数字，IPv4 不超过 32、IPv6 不超过 128；没有前缀时按 /32 或 /128。
3. 通过后用 `Ipv4Cidr::from_prefix_and_bits` 或 `Ipv6Cidr::from_prefix_and_bits` 构造。
4. 主机位不为零的网段（如 `192.168.1.5/24`）照 cidr-utils 的做法清零后接受。

分类先检查原始地址是否属于本机；IPv4 映射和标准 NAT64 抽出内嵌 IPv4 后也执行本机、元数据和下表判断，`literal` 标志照传。再判其他硬拒，最后判软拒及放行。实际连接仍使用过滤过的原始 SocketAddr。

| 地址类别 | 默认结果、原因码 | 放行能否打开 |
|---|---|---|
| IPv4 `127/8`；IPv6 `::1` | `loopback` | 否 |
| IPv4 `169.254/16`（含 169.254.169.254）；IPv6 `fe80::/10`；元数据单地址 `fd00:ec2::254`（AWS IMDS）、`fd20:ce::254`（GCP，仅 IPv6 虚拟机）、`100.100.100.200`（阿里云 ECS） | `link_local` | 否 |
| 所有网卡上的本机地址，含虚拟、离线网卡和已弃用 IPv6；B11 的公网 IPv4 | `local` | 否 |
| open 严格解析出的 IPv4 `198.18/15`，含映射和 NAT64 内嵌形式 | `fake_ip_literal` | 否 |
| 未指定、组播、保留地址（见下表） | `reserved` | 否 |
| IPv4 私网、`100.64/10`；IPv6 `fc00::/7` | `lan` | 是 |
| 本机各 IPv4 的链路网段；全部本机全局 IPv6 所在 /64 | `lan` | 是 |
| 被控端解析出的 `198.18/15` | `fake_ip` | 是 |
| 其余地址 | 允许 | 不需要 |

保留地址用显式网段表实现，不复用 ICE 的分类函数（`ice/sig.rs:147-149` 把 `2000::/3` 一律当全局）。依据：IANA IPv4 和 IPv6 Special-Purpose Address Registry（两张表都是 Last Updated 2025-10-09，2026-10-27 查 https://www.iana.org/assignments/iana-ipv4-special-registry/ 和 https://www.iana.org/assignments/iana-ipv6-special-registry/）。
工具链钉在 Rust 1.99.1（总仓库 `scripts/windows/env.ps1:10`），方法可用性如下：

- 稳定、可以用：Ipv4Addr 的 `is_unspecified`、`is_loopback`、`is_private`、`is_link_local`、`is_multicast`、`is_broadcast`、`is_documentation`；Ipv6Addr 的 `is_unspecified`、`is_loopback`、`is_multicast`、`is_unique_local`（1.84）、`is_unicast_link_local`（1.84）、`to_ipv4_mapped`（1.63）。
- 仍是 nightly（`ip`，#27709），不能用：IPv4 的 `is_global`、`is_shared`、`is_benchmarking`、`is_reserved`；IPv6 的 `is_global`、`is_documentation`、`is_benchmarking`、`is_unicast_global`、`is_ipv4_mapped`。
- 不用 `Ipv6Addr::to_ipv4()`：它把 `::1` 变成 `0.0.0.1`，还把弃用的 `::a.b.c.d` 也当成内嵌 IPv4。

判定顺序：先判本机（`local`）和上表三个元数据单地址（`link_local`），再按下面各地址族的表从上到下，先命中的为准。元数据常量在软拒 `fc00::/7`、`100.64/10` 之前判；IPv4 映射和 NAT64 内嵌形式按抽取规则自动覆盖。

IPv4：

- `127/8` → `loopback`；`169.254/16` → `link_local`。
- `0/8`、`192.0.0.0/24`、`192.0.2.0/24`、`192.88.99.0/24`、`198.51.100.0/24`、`203.0.113.0/24`、`224/4`、`240/4`（含 255.255.255.255）→ `reserved`。
- `10/8`、`172.16/12`、`192.168/16`、`100.64/10` → `lan`。
- `198.18/15`：字面量为 `fake_ip_literal`，解析所得为 `fake_ip`。
- 其余按本机链路网段判断软拒，否则允许，包括 IANA 标为全局可达的 `192.31.196/24`、`192.52.193/24`、`192.175.48/24`。`192.0.0.9`、`192.0.0.10` 两个任播地址 IANA 也标为全局可达，这里随整段 `192.0.0.0/24` 一起拒。

IPv6：

- `::1` → `loopback`；`fe80::/10` → `link_local`。
- `::ffff:0:0/96`：用 `to_ipv4_mapped()` 取出内嵌 IPv4，按 IPv4 表判，`literal` 标志照传。
- `64:ff9b::/96`（条件 `u128::from(ip) >> 32 == 0x0064_ff9b_0000_0000_0000_0000`）：取低 32 位，按 IPv4 表判。
- `fc00::/7` → `lan`。
- 不在 `2000::/3` 里的其余地址（`segments()[0] & 0xe000 != 0x2000`）→ `reserved`。覆盖 `::`、`::/96`、`64:ff9b:1::/48`、`100::/64`、`100:0:0:1::/64`、`5f00::/16`、`fec0::/10`、`ff00::/8`。
- `2000::/3` 里的几段也按 `reserved`：`2001::/23`（`s[0] == 0x2001 && s[1] < 0x0200`，含 Teredo `2001::/32`、基准测试 `2001:2::/48`、ORCHID）、`2001:db8::/32`、`3fff::/20`（`s[0] == 0x3fff && s[1] < 0x1000`）、`2002::/16`。
- 其余按本机全局 IPv6 所在 /64 判断软拒，否则允许，包括 `2620:4f:8000::/48`。`2001::/23` 里 IANA 标为全局可达的任播和协议用地址（`2001:1::1~3`、`2001:3::/32`、`2001:4:112::/48`、`2001:20::/28`、`2001:30::/28`）随整段一起拒。

硬拒始终先于放行。内嵌 IPv4 的软拒按抽出的 IPv4 匹配 IPv4 放行规则，不能靠宽泛 IPv6 前缀绕过；本机原始 IPv6 的硬拒检查仍保留。`opened_message` 按 README §2.4：六种策略原因 `reserved/loopback/link_local/local/lan/fake_ip` 返回 `MSG_BLOCKED`；`fake_ip_literal` 返回 `MSG_FAKE_IP_LITERAL`；其余返回空串。不拼接地址、域名或系统错误。`MSG_NOT_ENABLED` 在 M-2 单独处理，不新增 B12 原因码。

### 3.2 `lan.rs`、共用 `dns.rs` 和 `ice/`

**网卡快照**：DadState、OnLinkPrefixLength 是 Windows `GetAdaptersAddresses` 报的地址状态和在链前缀长度；Preferred 是可用地址，已弃用的临时地址是 Deprecated。

1. `Nic`（`lan.rs:77-92`，带 `#[derive(Debug, Clone, Default)]`）在 `dns` 字段之后加 `ipv4_prefixes: Vec<(Ipv4Addr, u8)>`、`all_ipv6: Vec<Ipv6Addr>`。前者记每个 IPv4 的 `OnLinkPrefixLength`；后者收全部 IPv6 单播地址，不看 DadState，包含已弃用的临时地址。
2. `nics()` 的 `:421-422` 两个 `let mut` 之后加 `let mut ipv4_prefixes = Vec::new();` 和 `let mut all_ipv6 = Vec::new();`；`:425` `ipv4.extend(ipv4_of(&ua.Address));` 之后加 `ipv4_prefixes.extend(ipv4_of(&ua.Address).map(|ip| (ip, ua.OnLinkPrefixLength)));` 和 `all_ipv6.extend(ipv6_of(&ua.Address));`，都放在 `:426` 的 DadState 判断之外。
3. 前缀取自 `IP_ADAPTER_UNICAST_ADDRESS_LH::OnLinkPrefixLength: u8`（windows 0.61.1），IPv4 只接受 0~32，不猜 /24。`:390` 的 flags 不加 `GAA_FLAG_INCLUDE_PREFIX`，那个标志只影响 FirstPrefix 链表【推测，按文档】。
4. 唯一的生产字面量在 `:459-474`，在 `:473` `dns,` 之后加 `ipv4_prefixes,` 和 `all_ipv6,`。测试构造 `lan.rs:487-497`、`ice/gather.rs:367-384` 都有 `..Default::default()`，不用改。
5. 现有 `:426-439` 的 Preferred 筛选、`ipv6` 字段、`is_physical` 和 ICE 的候选选择保持原语义。

策略快照由全部 `Nic` 构造，不先筛物理网卡；全局 IPv6 按高 64 位形成 /64，不能用临时地址报告的 /128。连接和 DNS 的源地址只取在线、非虚拟、有对应地址族默认网关的可用物理地址，按网卡代价、链路速度排序。IPv4 源地址只排除回环、链路本地、未指定和 198.18/15，用 `exit/dial.rs` 的本地小函数，不用 ICE 的 `lan::excluded_ip`：后者还排除 100.64/10，而有的运营商把 CGNAT 地址直接分给电脑；Tailscale 一类网卡已由 `is_virtual` 排除。

**DNS 共用化**：新建 `libs/leapgate/src/dns.rs`。`lib.rs` 按字母序在 `pub mod brand;` 之后加 `pub(crate) mod dns;`；`ice/mod.rs:6` 的 `mod dns;` 保留。从 `ice/dns.rs` 挪进共用模块的只有报文部分：`TYPE_A`、`TYPE_AAAA`（`:27-28`）、`query`（`:151-168`）、`reply_to`（`:171-177`）、`answers`（`:182-210`）、`skip_name`（`:213-223`）。接收缓冲自己定义值为 1500 的常量（原值在 `ice/gather.rs:33`），不再 `use super::gather::RECV_BUF`（`ice/dns.rs:8`）。共用模块只做单服务器查询，不依赖 `ice::LocalAddr` 或 ICE 的分类器：

```rust
pub(crate) enum Answer { Addresses(Vec<IpAddr>), Negative, NoAnswer }
/// `server`'s A and AAAA answers for `host` by `deadline`, from a socket of its own on `bind`.
/// Once one family has addresses, the other one is waited for at most `other_family_grace`.
pub(crate) async fn ask(
    bind: IpAddr, server: SocketAddr, host: &str, deadline: Instant,
    other_family_grace: Option<Duration>,
) -> Answer;
```

`ask` 照 `ice/dns.rs:104-148`：同一 socket 发 A、AAAA 两个查询，各用一个随机事务号；丢掉不是 `server` 发来的包，按事务号、QR、问题数和问题段匹配。结果分三态：

- 有 A 或 AAAA 地址：`Addresses`。
- 匹配的 NXDOMAIN（RCODE 3），或两个查询都是 NOERROR 但没有地址：`Negative`。
- 其余情况（超时、收发出错、SERVFAIL、REFUSED 等其他非 0 RCODE、TC 截断位 `resp[2] & 0x02` 置位、格式错误、名字不合法）且没有地址：`NoAnswer`。

`answers` 要区分 RCODE、检查 TC 位。现状：任何非 0 RCODE 都返回 `Some(空)`（`:186-188`），格式不对返回 `None`；`ask` 在 `:138` 用 `unwrap_or_default()` 把两种都压成空；TC 位没有检查。

**出口怎么用**：`dial` 从选中的物理源组出“（源地址，服务器）”对。每个源配它那块网卡 `Nic.dns` 里同一地址族的服务器，排除回环、链路本地、`fec0::/10`（含 Windows 在没配 IPv6 DNS 的网卡上填的 `fec0:0:0:ffff::1~3` 占位地址）和 `198.18/15`，按源的排序去重后取前两台。用本地小函数，不用 ICE 的 `sig::classify`。出口并发问这两台，`other_family_grace` 传 50 ms（RFC 8305 §3 的 Resolution Delay），一族已有地址时另一族最多再等 50 ms；不引入公共 DNS 或 DoH。任一台先返回 `Addresses` 就立即采用，丢弃另一台的查询，不等它到期（同 `ice/dns.rs:54-92` `resolve_via` 的 `select_ok` 竞速）；两台都没有地址时才合并：有明确否定为 `Negative`，其余为 `NoAnswer`。部分族无地址、另一族未回答不能断言不存在。
出口只有 `NoAnswer` 才回落系统解析。系统解析可提前并行启动以共用 2 秒期限，但物理 DNS 有地址或明确否定时不得采用系统答案；原始地址被出口策略拒绝不触发系统重查。系统结果也逐个经过 §3.1，不能把 `127.1`、带区域 ID 的 IPv6 等系统认可的写法当绕过路径。

**ICE 侧**：`ice/dns.rs` 保留 `RESOLVE_WAIT`、`MAX_SERVERS`、`resolve`、`resolve_via`（`:25-92`，`select_ok` 竞速和系统回落不变）和 `reachable`（`:95-100`）。原 `ask` 改成适配层：调用共用 `ask(…, None)`，`Addresses` 加端口后经 `reachable` 过滤，非空返回 `Ok`、为空返回 `Err(())`；`Negative`、`NoAnswer` 都返回 `Err(())`（原来 NXDOMAIN 也是 `Err`）。每台服务器仍先按 ICE 分类过滤再竞速，只回 fake-ip 的服务器照旧让位给下一台。唯一调用点 `ice/mod.rs:101`（`dns::resolve(local, rendezvous, started + dns::RESOLVE_WAIT)`）、签名 `ice/dns.rs:32-36` 和 200 ms 期限不变，不改 ICE 协议或候选。
测试：`:259-353` 的报文测试随代码挪进 `dns.rs`，`:310` 断言 RCODE 3 得 `Some(vec![])` 的那一行按三态改写；`fake_server` 和 `the_adapters_answer_wins_and_the_system_one_is_kept_only_if_reachable`（`:352-403`）留在 `ice/dns.rs`，断言不改，它们用到的 `record`、`reply` 在 `dns.rs` 里改成 `#[cfg(test)] pub(crate)`。

### 3.3 `exit/dial.rs`：解析、过滤、连接与日志

```rust

    Result<std::io::Result<tokio::net::TcpStream>, tokio::time::error::Elapsed>;
```

`connect` 返回的 future 必须是 `Send`（`server/port_forward_mux.rs:149` 用 `tokio::spawn` 跑 `run_controlled_channel`），跨 await 不能持有 `std::sync::MutexGuard`、`Rc` 这类类型；tokio 照 `rendezvous.rs:1` 用 `use hbb_common::tokio;` 引入，不往 `libs/leapgate/Cargo.toml` 加 tokio 依赖。
错误通过 `io::Error` 内的自有错误类型携带 `Reason`，不能先变字符串再猜原因。`failure_message` 成功返回 `None`；失败返回 `Some(固定文案或空串)`，外层超时映射 `timeout`。这些类型仅供主 crate 挂钩，不依赖上游通道对象。

流程和取值：

1. 从进入 `connect` 起套整体 10 秒期限。检查主机和端口，读 Config 的 `leapgate-exit-allow-nets`（`hbb_common::config::Config::get_option(super::OPTION_ALLOW_NETS)`，常量在 S0），用 `policy::parse_allow_nets` 解析，失败按空放行列表处理（§3.1）；用 `spawn_blocking` 枚举一次网卡，构造本机快照和物理源地址。
2. 先 `host.parse::<IpAddr>()`；成功为字面量、不查 DNS。失败才走域名解析，完整解析阶段至多 2 秒，不把目标拼成 `host:port` 交给连接 API。
3. B11 公网 IPv4 探测或缓存读取完成、并入 `Snapshot` 后，IP 字面量（`literal = true`），以及物理 DNS 或系统回落取得的每个地址（`literal = false`），都用同一个快照调用同一个 `classify`。去重，丢掉被拒地址，最多保留 8 个通过者；有通过者就继续，不能因混有内网答案整项拒绝。全被拒时返回按解析顺序遇到的第一个策略原因。
4. IPv6、IPv4 各保留族内顺序，从 IPv6 开始交错；只有一族时原样。纯函数 `attempt_order(&[IpAddr]) -> Vec<IpAddr>` 接收过滤后的地址、最多返回 4 个；按此顺序间隔 250 ms 尝试，连接阶段共用 8 秒期限，并受整体 10 秒约束。
5. 每次用 `TcpSocket::new_v4/new_v6`，绑定匹配地址族的物理源地址及端口 0，再 `connect(filtered_socket_addr)`。优先选目标所在链路的物理源，否则按网卡排序选；无匹配源为 `no_route`，绝不回落未绑定连接。
6. 第一个成功的连接胜出，丢弃其他 future 和 socket；不另 spawn 无人回收的连接任务。不读取 RustDesk socks、系统代理或 VPN 设置。

地址过滤在实际连接前完成，连接不再次解析域名。网卡 DNS 返回被拒地址不触发系统重查。没有地址时：明确否定为 `nxdomain`，解析不可用为 `resolve_failed`；连接期限为 `timeout`、拒绝连接为 `refused`、无可用源或路由为 `no_route`，其余连接错误为 `unreachable`。多次连接全失败取最后完成尝试的原因，期限到则为 `timeout`。

**本机公网 IPv4（B11）**：在 `ice/mod.rs` 加函数（补 `use std::net::Ipv4Addr`），复用 ICE 的物理源选择、会合服务器解析和 Binding 探测，不建 ICE 会话、不发信令：

```rust
/// Phase 4 B11: the IPv4 mappings the rendezvous server `rendezvous` (`host:port`) reports
/// for the physical IPv4 addresses, within `GATHER_WAIT` including the name lookup.
pub(crate) async fn public_v4(nics: &[lan::Nic], rendezvous: &str) -> Vec<Ipv4Addr> {
    let started = Instant::now();
    let local: Vec<LocalAddr> = gather::select(nics).into_iter().filter(|l| l.ip.is_ipv4()).collect();
    let stun = dns::resolve(&local, rendezvous, started + dns::RESOLVE_WAIT).await;
    let Some(&server) = stun.iter().find(|s| s.is_ipv4()) else { return Vec::new() };
    let mut bound = Vec::new();
    for l in &local {
        if let Ok(s) = gather::bind(SocketAddr::new(l.ip, 0)).await { bound.push(s); }
    }
    let targets = vec![Some(server); bound.len()];
    let mut socks = Socks::new(bound);
    socks.ask(&targets, started + GATHER_WAIT).await.into_iter().flatten()
        .filter_map(|m| match m.addr.ip() { IpAddr::V4(ip) => Some(ip), IpAddr::V6(_) => None })
        .collect()
}
```

## 7. 已知限制

- 目录不是关口，撤销目录授权不终止会话；知道密码的人仍能手填 ID。做不到只给出口不给远控，控制端 ID 自报，日志不能归责到登录账号。关出口会断出口会话；改密码不承诺立即切断已认证会话。
- 局域网默认拒绝只约束出口模式。它防的是：经出口浏览的第三方网页借出口攻击被控端局域网（DNS 重绑定、对路由器管理页的 CSRF）；以后开了系统代理时，控制端访问自家局域网的请求被送到对面去。它不防的是：密码持有者用普通 TCP 隧道或远控桌面去碰局域网；关闭普通隧道也不限制远控桌面本身。
- access-mode 设成“仅共享屏幕”不关闭出口；已信任设备只免 2FA。直接 IP 访问的未加密流不能当出口，其他未加密路径可能先出现上游不安全确认框。
- 放行全局 IPv6 /64 会随家宽前缀变化失效。路由器默认 fake-ip 需要主人明确放行才能用域名；路由器用的不是默认 fake-ip 网段（198.18.0.0/15）时判不出来，这些假地址会被当成公网放行，路由器把它转到哪里（包括局域网），出口都管不了。本机 strict-route 阻断物理 DNS 时可能只能失败，放行不保证可用。
- 局域网保护只认得出本机看得到的范围：IPv6 只认本机地址所在的 /64，同一委派前缀下的其他 /64（访客、IoT 网段）和路由器 WAN 侧的 IPv6 地址都按公网放行（后者从内网访问时路由器常按 LAN 区规则放行，管理页可能打得开【推测】）；路由器上用自定义前缀（不是 `64:ff9b::/96`）做 NAT64 时，判不出内嵌的局域网 IPv4；B11 用 STUN 测到的是 UDP 出口，路由器也代理 UDP 或有多条 WAN 时，那个地址不一定是 TCP 实际出去的 WAN 地址。
- 公网 IPv4 查不到或缓存尚未更新时（含换网络后最长 10 分钟），NAT 回环保护不完整；原版服务端或 UDP 不通可能没有 STUN 结果。网卡快照到连接之间的地址变化也存在时间窗口。
- 出口绕过本机代理和 VPN，不能借主人的公司 VPN 进内网；物理网络打不开的站点也不会因出口而可达。物理网卡识别沿用 IfType 和关键字，不能声称已验证所有虚拟网卡实现。
- 解析超时取消等待不保证操作系统的阻塞解析立即停止。物理 DNS 不读 hosts，和系统分离 DNS 的结果可能不同。为共用 2 秒期限，系统解析和物理 DNS 同时发起：即使最终采用物理 DNS 的答案，目标域名也会经系统解析器发给本机的代理、VPN 或公司 DNS（系统答案照旧不采用，连接照旧绑物理网卡），每次解析还占一个阻塞线程，直到操作系统返回。
- 单会话两个方向各最多约 64 MiB 缓存；主循环一次发送可能阻塞至 120 秒，因此每秒检查不构成所有负载下“2 秒内关闭”的硬实时保证。所有通道共用发送队列和有序隧道，吞吐、队头阻塞及 KCP 限制见 README §7。
- 只记录每分钟第一个被拒 IP 及累计次数，不能完整还原拒绝历史。控制端通道层乐观应答，普通失败只表现为连接关闭，固定策略文案按上游规则去重。
