## 0. 结论先行

1. `APP_NAME` 改成 Porta 以后，Windows 上的服务名、卸载注册表项、安装目录、配置目录、IPC 管道、URL scheme、托盘互斥量、防火墙规则名、快捷方式名、打印机队列名都会跟着变，共存的大部分问题由此解决【读码】。**`ORG` 只在 macOS 上编译**，Windows 上它不影响任何东西【读码】。
2. 改名解决不了的共存问题，集中在**全机共享的东西**：
   - 虚拟显示驱动：当前默认实现是第三方 Amyuni 的 `usbmmidd`，不是 RustDeskIddDriver。
   - 打印机驱动名 `RustDesk v4 Printer Driver`。
   - 两个固定端口：局域网发现 UDP 21119、直连 TCP 21118。
   - 一个写死的旧 Inno Setup 卸载键 `IS1`。
   - 隐私模式进程名 `RuntimeBroker_rustdesk.exe`，以及卸载脚本和 MSI 里按这个名字杀进程。

   **任意一方卸载，都会顺手卸掉 Amyuni 虚拟显示驱动**，影响另一方【读码】。
3. 官方外呼里，**真会自动发生的只有一处：没配服务器时向 `rs-ny.rustdesk.com` 注册**，靠 porta-cardo 改 `RENDEZVOUS_SERVERS`/`RS_PUB_KEY` 解决（方案 §3.2 已定）。
   - 还有一个方案里没写到的坑：默认 API 地址 `https://admin.rustdesk.com` 写死在 `src/common.rs` 的 `get_api_server_` 里，**不随 `RENDEZVOUS_SERVERS` 变**。没配服务器时，用户点"登录"会请求 RustDesk 官方的登录接口。"是否在用公共服务器"的判断（`using_public_server`）也是这样，所以主页还会显示指向官方定价页的提示【读码】。只改 `RENDEZVOUS_SERVERS` 不够，还要设 `PROD_RENDEZVOUS_SERVER` 或默认设置。
   - 检查更新、自动更新、下载器在改名后都走不到，但守卫条件不完全一样（见 §3.2）。
   - 其余都是用户点了才打开的帮助、隐私政策、官网链接。
4. 打开 IPv6 打洞后，客户端会向 4 个**第三方** STUN 服务器（Cloudflare、Google、antisip、nextcloud）查询自己的公网 IPv6 地址。这和方案 §3.8"第一期开 IPv6 打洞"直接相关，方案里没有提到【读码】。
5. 翻译：`src/lang.rs` 的 `translate_locale` 在运行时把 "RustDesk" 替换成应用名，Flutter 的 `translate()` 走的就是它【读码】。但 Dart 里写死、没经过 `translate()` 的字符串不会被替换，例如桌面主窗口标签栏标题、关于页的版权行。

## 1. 品牌：`APP_NAME` 和 `ORG`

### 1.1 定义
- `libs/hbb_common/src/config.rs`：
  - `APP_NAME: RwLock<String> = "RustDesk"`，所有平台都有【读码】。
  - `ORG: RwLock<String> = "com.carriez"`，**在 `#[cfg(target_os = "macos")]` 块里，只有 macOS 编译**【读码】。05 笔记说 `ORG` 管 macOS/Linux 的配置目录，要更正：`Config::path` 在非 macOS 上直接用 `let org = "".to_owned()`。
- 运行时只有一处会改写 `APP_NAME`：`src/common.rs` `read_custom_client()` 读 `custom.txt` 里的 `app-name`。这个文件要用 RustDesk 官方私钥签名，Porta 不用（方案 §3.10）【读码】。
- 所以 Porta 只需要在 porta-cardo 里把 `APP_NAME` 的默认值改成 `"Porta"`（macOS 以后再改 `ORG`）。exe 文件名不会反过来影响 `APP_NAME`【读码】。
- 判断函数（`src/common.rs`）：
  - `is_rustdesk()`：`APP_NAME == "RustDesk"`。
  - `is_custom_client()`：`get_app_name() != "RustDesk"`。
  - `get_uri_prefix()`：`"{小写 app_name}://"`【读码】。

### 1.4 驱动名：列出来，按方案不改
- **虚拟显示**：`src/virtual_display_manager.rs` 里 `const IDD_IMPL: &str = IDD_IMPL_AMYUNI`，**当前默认用的是 Amyuni 的 `usbmmidd`**，不是 RustDeskIddDriver【读码】。
  - Amyuni：硬件 ID `usbmmidd`，INF `usbmmidd_v2\usbmmIdd.inf`，设备串 "USB Mobile Monitor Virtual Display"，安装工具 `deviceinstaller64.exe`。
  - CI 从 `github.com/rustdesk-org/rdev/releases/download/usbmmidd_v2/usbmmidd_v2.zip` 下载，放在 exe 同级目录（`.github/workflows/flutter-build.yml` 第 336 行）【读码】。
  - RustDeskIddDriver（`RUSTDESK_IDD_DEVICE_STRING = "RustDeskIddDriver Device"`，`libs/virtual_display/dylib/src/win10/mod.rs` `DRIVER_INSTALL_PATH`）还留着代码路径，但 Flutter 版 CI 不打包它的 INF【读码：workflow 里搜不到】。方案 §3.10 写"不改驱动名（RustDeskIddDriver 等）"，建议改成"不改 Amyuni usbmmidd 和打印机驱动"。
- **打印机**：驱动名 `"RustDesk v4 Printer Driver"`（`libs/remote_printer/src/lib.rs` `get_driver_name`；MSI `CustomActions/RemotePrinter.cpp` 同样写死），INF `drivers/RustDeskPrinterDriver/RustDeskPrinterDriver.inf`。CI 从 `github.com/rustdesk/hbb_common/releases/download/driver/rustdesk_printer_driver_v4-1.4.zip` 下载，并核对 sha256【读码】。
- **为什么不改**：
  - 驱动包的签名是对 `.cat` 编目文件签的，编目里有包内每个文件（含 INF）的哈希。INF 里哪怕改一个字节，签名就失效，必须重新提交微软签名或者自己签【一手来源：https://learn.microsoft.com/en-us/windows-hardware/drivers/install/catalog-files ，2026-10-22】。
  - 驱动显示名、设备描述都写在 INF 里，改名就意味着重签，和"前两期不签名"冲突。
  - 打印机驱动名虽然是代码里传给 spooler 的字符串，但必须和 INF 里声明的模型名一致才能装上【推测】，所以同样不能单独改。

1. 先装原版再装 Porta，反过来再装一遍；两边服务都在跑，托盘各一个。

## 4. 翻译：运行时替换 "RustDesk"

- 机制【读码：`src/lang.rs` `translate_locale`】：
  - 先查当前语言的表，查不到再查英文表，再查不到就返回 key 本身。三种情况都会经过同一个 `replace` 闭包。
  - `!is_rustdesk()` 时，把译文里的 "RustDesk" 替换成 `get_app_name()`。
  - 有两个例外不替换：key 以 `upgrade_rustdesk_server_pro` 开头的，和 `powered_by_me`（所以 #11 那行小字仍然是 "Powered by RustDesk"）。
  - 应用名本身含 "RustDesk" 时，先用占位符保护再替换。"Porta" 不含，走简单替换。
