## 0. 结论先行

视频上屏这一条（把 Rust 解出的帧低拷贝/零拷贝显示进界面，60fps 1080p/4K 可行），按过关程度分三档：

- **过关（有官方 API，生产可用）**：Flutter（基线）、Qt/QML（cxx-qt）、Slint、egui、Iced。
- **有条件（能做，但靠未稳定或内部 API）**：Dioxus Native（Blitz 仍是预发布）、Compose Multiplatform（零拷贝只能反射 Skiko 内部对象，社区项目做到了）。
- **不过关**：Tauri v2（WebView 内没有原生纹理入口，只能"原生 surface 垫在透明 WebView 下面"，Linux 上会闪烁/不支持 Wayland）、GPUI 官方版（只有 macOS 的 CVPixelBuffer 零拷贝，Win/Linux 每帧走 CPU 上传图集）。

是否值得换掉 Flutter（推测，供拍板）：
- Flutter 的长期成本主要在两点：桌面官方多窗口到 2026-10 仍是 main 通道实验特性；3.47 起桌面默认 Impeller，RustDesk 依赖的 Windows D3D11 外部纹理路径在 Impeller 下刚出过两次崩溃（都已修，但说明这条路径不是 Flutter 团队的主测路径）。
- 如果换，能同时满足"视频零拷贝 + 现代化 UI + 五平台 + 与 AGPL 兼容"的只有 **Qt/QML** 和 **Slint** 两个；egui/Iced 视频没问题，但"现代化设计"和移动端是短板。
- 不换的理由同样硬：上游现成的 Flutter 界面、frb 绑定、外部纹理插件都能直接复用；换框架等于整套 UI 重写，并且要自己重做 RustDesk 已经踩过的坑。

## 1. 共性背景（对所有候选都成立）

- **"零拷贝"在远程桌面里的含义**：上游 RustDesk 的解码器（vpx/aom 软解、hwcodec 硬解）大多吐出 CPU 内存里的 YUV/RGBA；只有 Windows 硬解路径能直接得到 D3D11 纹理。所以对多数平台，现实目标是"一次 CPU→GPU 上传"，而不是严格零拷贝（推测，基于上游架构，详见 01/02 号笔记）。1080p60 RGBA 约 0.5 GB/s，4K60 约 2 GB/s，单次 `write_texture`/`glTexSubImage` 在独显和近年核显上都扛得住（推测）。
- **键盘全局捕获**（Win 键、Alt+Tab 透传等）在 RustDesk 里是 Rust 侧用系统级钩子（rdev / 低级键盘钩子）做的，和 UI 框架基本无关；但 UI 框架会不会先吞键、焦点是否稳定会影响体验。WebView 类方案键盘事件发生在 WebView 进程里，问题最多（推测 + Tauri 插件文档旁证，见第 4 节）。
- **AGPL-3.0 兼容性**：MIT/Apache-2.0/BSD 都可以并入 AGPL 作品；GPLv3 可以和 AGPLv3 组合（GPLv3 第 13 条与 AGPLv3 第 13 条互相允许）；LGPLv3 动态或静态链接都可，只要满足 LGPL 的可替换要求（推测，基于许可证文本的通行理解，不是律师意见）。

## 2. Flutter（基线）

### 2.1 视频上屏 —— 过关，但 Impeller 切换带来新风险
- 官方桌面外部纹理 API：`flutter_texture_registrar.h` 提供 `kFlutterDesktopPixelBufferTexture`（CPU 像素缓冲）和 `kFlutterDesktopGpuSurfaceTexture`，后者在 Windows 支持 `DxgiSharedHandle` 和 `D3d11Texture2D` 两种（一手）。
  - https://api.flutter.dev/windows-embedder/flutter__texture__registrar_8h_source.html
- Windows 上 GPU surface 纹理经 ANGLE 的 `EGL_D3D_TEXTURE_2D_SHARE_HANDLE_ANGLE` 导入；不支持 `IDXGIKeyedMutex` 同步，社区抱怨要额外 Flush/中间拷贝（一手：issue 讨论）。
  - https://github.com/flutter/flutter/issues/164507
- **Impeller 下的回归**（一手）：
  - #190774：Impeller 下 GPU surface 外部纹理在路由切换快照时崩溃于 `EmbedderExternalTextureGL::ResolveTextureSkia`；PR #191017 于 2026-08-17 合入 master，标了 `cp: stable`。https://github.com/flutter/flutter/issues/190774 、https://github.com/flutter/flutter/pull/191017
  - #191468：Impeller 下 DXGI 共享句柄外部纹理首帧即崩，维护者让在 main 上复测，2026-09-03 报告者确认 main 已不复现并关闭。https://github.com/flutter/flutter/issues/191468
  - 所以 3.47.x stable 是否已含全部修复，要以具体补丁版本为准（PR #191017 的 3.47 cherry-pick 只在旁证里看到，未在一手页面确认）。
- 注意：3.47 官方博客说 Windows/Linux 上 Impeller 走 Vulkan，但 #190774 的日志显示 Windows 默认后端是 `OpenGLESSDF`（经 ANGLE）；Windows 的 Vulkan 后端 PR（#183382 拆分后的 #189586）还在 draft，且明确"ANGLE/OpenGL 仍是默认和回退"（一手，两份一手资料表述不一致，以代码/issue 为准）。https://github.com/flutter/flutter/pull/183382
- 移动端：Android 的旧 `SurfaceTexture` 外部纹理在 Impeller+Vulkan 下"永远不会支持"，需要迁到 `SurfaceProducer`（一手：engine 提交说明）。https://chromium.googlesource.com/external/github.com/flutter/flutter/+/5b9bb4bacf3c21669f71f873fffc07fd24c789a1%5E%21/

### 2.2 多窗口 —— 官方 API 仍是实验特性
- Flutter 3.41 引入实验性多窗口 API；3.44 博客原话是窗口特性"只在 main 通道、尚不适合生产"；Canonical 自 2026-05 起任 Flutter 桌面主维护方（一手）。
  - https://flutter.dev/blog/whats-new-in-flutter-3-44
- 2026-08-24 官方博客《Introducing the Desktop Windowing API》：五种窗口类型（regular/dialog/tooltip/popup/satellite），所有窗口共享一棵 widget 树（不再一窗一 engine），但仍在 main 通道、`flutter config --enable-windowing` 开关后面（一手）。https://flutter.dev/blog/desktop-windowing-apis
- 3.47 release notes 里窗口 API 还有破坏性改名（`preferredSize`→`size`）（一手）。https://docs.flutter.dev/release/release-notes/release-notes-3.47.0
- 上线前清单 issue #177586 仍 open（一手）。https://github.com/flutter/flutter/issues/177586
- 现状推论：stable 通道上做多窗口只能继续用社区插件 `desktop_multi_window`（RustDesk 正在用，一窗一 engine 一 isolate，跨窗通信走 method channel）（旁证：https://startdebugging.net/2026/08/how-to-enable-multi-window-support-in-a-flutter-desktop-app/ ）。等官方 API 进 stable 后迁移，能省内存、共享状态，但迁移本身是一笔工作量（推测）。

### 2.3 Impeller 桌面状态
- 3.47（2026-08-12）起 macOS/Windows/Linux 默认 Impeller，可临时退回 Skia，官方说"未来版本会移除退回选项"（一手）。
  - https://flutter.dev/blog/whats-new-in-flutter-3-47
  - https://docs.flutter.dev/perf/impeller
- 对 Porta 的含义（推测）：上游钉在 3.24.5（Skia），升级到 3.47+ 会同时碰上 Impeller 切换和外部纹理路径变化，Windows D3D11 零拷贝那条要重新回归测试。

### 2.4 flutter_rust_bridge v2
- 活跃维护：2.12.0（2026-03-29）、2.13.0（2026-08-23）、2.14.0-beta.2（2026-09-12）；MIT；维护者 fzyzcjy（一手：docs.rs / pub.dev 版本列表）。
  - https://docs.rs/crate/flutter_rust_bridge/latest
  - https://pub.dev/packages/flutter_rust_bridge/changelog
- 2.10/2.11（2025-05~07）到 2.12（2026-03）之间有约 9 个月空档，单人维护的风险存在（一手日期，风险判断为推测）。
- 上游 RustDesk 用的是 1.80，迁到 v2 需要重生成绑定、改调用方式（推测）。

### 2.5 其他
- 平台：五个平台都稳定（一手：https://docs.flutter.dev/platform-integration/desktop ）。Linux 走 GTK 嵌入器，支持 Wayland。
- 许可证：BSD-3，可与 AGPL 一起分发。
- IME/无障碍：成熟，桌面有 Semantics；中文 IME 在 Windows/macOS 可用（推测，基于广泛生产使用，未逐项核对 2026 issue）。
- 成熟度：每年 4 个 stable；3.47.6（2026-10-01）为当前 stable（旁证：搜索摘要）。

## 3. Qt/QML（经 cxx-qt 接 Rust）

### 3.1 视频上屏 —— 过关，原生纹理导入是所有候选里最全的
- Qt Quick 官方提供 `QNativeInterface::QSGD3D11Texture / QSGD3D12Texture / QSGMetalTexture / QSGVulkanTexture / QSGOpenGLTexture::fromNative()`，把已有的原生纹理包装成场景图纹理（一手）。
  - https://doc.qt.io/qt-6/qnativeinterface-qsgd3d11texture.html
  - https://doc.qt.io/qt-6/qtquick-module.html
- 限制：D3D11 版"目前只适合 2D RGBA 纹理"，必须在渲染线程调用，且纹理须和 Qt Quick 用同一个 device（可用 `QQuickGraphicsDevice` 让 Qt 用外部 device）（一手）。https://doc.qt.io/qt-6/qquickwindow.html
- 另有 `QQuickRhiItem`（6.7+）做自定义渲染、`createTextureFromRhiTexture`（6.6+）（一手）。https://doc.qt.io/qt-6.11/qtquick-scenegraph-rhitextureitem-example.html
- 同类旁证：Moonlight PC 客户端用 Qt（构建需 Qt 6.11 SDK），硬解 H.264/HEVC/AV1/HDR（一手：仓库 README）。https://github.com/moonlight-stream/moonlight-qt
- 结论：Windows 硬解出来的 D3D11 纹理可以直接进 QML，NV12 需要自己写 shader 转 RGBA 或用 Qt Multimedia 的 `QVideoSink`（推测）。

### 3.2 多窗口 / 高 DPI / IME / 无障碍
- 多窗口、多显示器、分数缩放、IME、屏幕阅读器都是 Qt 的强项（推测，基于 Qt 长期生产使用；本次未逐项核对 2026 issue）。

### 3.3 平台
- Windows/macOS/Linux（X11+Wayland）/Android/iOS 都是正式支持平台（推测，Qt 6 官方支持平台页未在本次抓取）。

### 3.4 Rust 互操作 —— 成本最高的一项
- cxx-qt 由 KDAB 维护，MIT/Apache-2.0；2026 年发了 0.8.1（02-17）、0.9.0（06-23）、0.9.1（07-03）、0.10.0（08-24）；0.8 起构建 API 宣布稳定，0.9 加了 Qt Minimal（cargo 自动下 Qt）（一手）。
  - https://github.com/KDAB/cxx-qt/blob/main/CHANGELOG.md
  - https://kdab.github.io/cxx-qt/book/getting-started/6-cargo-qt-minimal.html
- cxx-qt 只覆盖 QObject/属性/信号槽这一层；QQuickItem 自定义渲染、原生纹理导入这类要写 C++ 再用 cxx 桥接（一手：crate README 原意是"未覆盖的部分直接写 C++"）。https://crates.io/crates/cxx-qt
- 实际意味着项目里要有 Rust + C++ + QML 三种语言，构建链要带 Qt SDK（推测）。

### 3.5 许可证
- Qt 开源版是 LGPLv3/GPL，部分模块只有 GPL（如 Qt Quick 3D、Qt Virtual Keyboard、Qt Graphs、Qt Wayland Compositor 等）（一手）。https://doc.qt.io/qt-6/licensing.html
- Porta 本身是 AGPL，LGPL 和 GPL-only 模块都能用；只是要遵守 LGPL 的可替换/提供源码义务（推测）。

### 3.6 包体积
- 没找到可靠的 2026 实测数据，不写数字。量级上 Qt Quick 应用带 Qt 运行库，明显大于 Rust 原生框架（推测）。

## 4. Tauri v2（WebView）—— 视频上屏不过关

- **视频**：WebView 里没有导入原生纹理的 API。社区做法有三种：
  1. IPC/WebSocket 把帧发给前端画 canvas —— 作者自己说"太慢"（旁证）。https://github.com/clearlysid/tauri-wgpu-cam
  2. 窗口底层用 wgpu 画、上面叠透明 WebView（需 `unstable` feature 的多 webview）—— Windows/macOS 可行；Linux 上 GTK 窗口和 wgpu 抢同一 surface 会闪烁，官方维护者说"Wayland 上根本不可能"这种子窗口方案（一手：issue 评论）。https://github.com/tauri-apps/tauri/issues/9220
  3. 在 WebView 里用 WebCodecs 解码 —— 这就绕开了 Rust 引擎的解码器，不符合"复用引擎"的目标（推测）。
  - 一个 2026-03 的 Tauri 远程桌面项目 drift-rdp 正卡在方案 2 的分层问题上（旁证）。https://github.com/CREVIOS/drift-rdp/issues/14
- **键盘**：WebView2 在独立进程里处理输入，一些快捷键要在前端拦截再转给 Rust（旁证：Steam overlay 插件文档的经验）。https://crates.io/crates/tauri-plugin-steam-overlay-surface
- **版本**：2.12.5（2026-10-21）为当前 v2；v3.0.0-alpha.0（2026-09-13）到 alpha.5（2026-10-14），v3 把运行时拆成可选的 wry（系统 WebView）或 CEF（自带 Chromium），Linux 加入 GTK4 支持（一手）。
  - https://github.com/tauri-apps/tauri/releases
  - https://newreleases.io/project/github/tauri-apps/tauri/release/tauri-v3.0.0-alpha.0 （聚合站转载 release notes，内容与官方一致，算旁证）
- 许可证 MIT/Apache-2.0；五平台都支持（移动端 v2 起正式）。
- 结论：做连接管理、设置、地址簿这类"非视频窗口"很合适；会话窗口不合适。混搭（会话窗口用原生 wgpu 窗口、其余用 Tauri）是可行的折中，但等于维护两套 UI 技术（推测）。

## 5. Slint —— 过关

- **视频**（一手）：
  - `Image::try_from(wgpu::Texture)` 导入 wgpu 纹理，要求和 Slint 共用同一 `wgpu::Device/Queue`（`WGPUConfiguration::Manual` 或渲染回调里拿），格式只支持 `Rgba8Unorm`，用法需含 `TEXTURE_BINDING|RENDER_ATTACHMENT`。https://docs.slint.dev/latest/docs/rust/slint/wgpu_30/
  - 该能力挂在 `unstable-wgpu-NN` feature 后面，随 wgpu 大版本换模块（当前 28/29/30 并存），文档明说"可能在小版本中移除或改变"。https://docs.slint.dev/latest/docs/rust/slint/wgpu_29/
  - 另有 `BorrowedOpenGLTextureBuilder` 导入 GL 纹理（不能跨窗口共享）和 `SharedPixelBuffer`（CPU 缓冲）。https://docs.slint.dev/latest/docs/rust/slint/struct.BorrowedOpenGLTextureBuilder
  - 2026-10 master 上 Vello 渲染器也支持了 wgpu 纹理导入（PR #13975），Skia 渲染器跨 wgpu 版本导入的修复（PR #13904）。https://github.com/slint-ui/slint/pull/13975
  - 未解决 issue #13203：Skia+WGPU 下导入的不透明纹理被当作非预乘 alpha 混合、局部重绘失效（会多耗 GPU，对全屏视频影响待测）。https://github.com/slint-ui/slint/issues/13203
- D3D11 硬解纹理要进 Slint，需要先导入成 wgpu 纹理（wgpu-hal 层 `from_raw`/共享句柄），这是额外工作；社区库 wgpu-graft 专门做"原生纹理→wgpu"（旁证）。https://github.com/merely-made/wgpu-graft
- **平台**：Windows/macOS/Linux（winit，含 Wayland）稳定；Android 支持 Rust 和 C++（C++ 自 1.17）；iOS 只支持 Rust，1.18 修了"iOS 应用意外走软件渲染"等问题，说明 iOS 还在打磨期（一手）。
  - https://docs.slint.dev/latest/docs/slint/guide/platforms/mobile/ios/
  - https://github.com/slint-ui/slint/blob/master/CHANGELOG.md
- **IME/无障碍**：AccessKit 无障碍；1.18 才让屏幕阅读器读到文本输入内容；1.18 修了"Windows 死键立即输出"和"IME 候选位置不跟随"（一手 CHANGELOG）。说明 IME 可用但细节还在补（推测）。
- **多窗口**：每个 `Window` 组件独立窗口，支持多窗口（推测，基于 API 设计；没有找到专门文档页）。
- **成熟度**：约每两三个月一个小版本：1.14（2025-10-21）、1.15（2026-02-04）、1.16（04-16）、1.17（06-24）、1.18（09-16）、1.18.1（09-21）；维护方是 SixtyFPS GmbH（Slint 公司）（一手）。https://github.com/slint-ui/slint/releases 、https://slint.dev/blog/slint-1.18-released
- **许可证**：GPLv3 / 免版税（不含嵌入式）/ 商业三选一（一手）。https://slint.dev/pricing
  - Porta 用 GPLv3 授权即可；GPLv3 与 AGPLv3 可组合（推测，许可证文本层面）。注意：这意味着 Porta 以后若想改闭源也没法用 GPL 版 Slint，但 Porta 本来就因 AGPL 不能闭源，所以不是新增约束。
- **Rust 互操作**：Rust 原生，`.slint` DSL 编译成 Rust，成本最低之一。
- **包体积/内存**：官方定位能跑在 MCU 上，但桌面带 Skia/wgpu 时体积另算；没找到可靠桌面实测数据（不写数字）。

## 6. egui / eframe —— 视频过关，"现代化设计"是短板

- **视频**：`egui_wgpu::Renderer::register_native_texture` 可把自己的 wgpu `TextureView` 注册成 egui 纹理；eframe 0.28 起在 `Frame` 上暴露 `register_native_texture`（一手 CHANGELOG）。https://github.com/emilk/egui/blob/HEAD/crates/eframe/CHANGELOG.md
- 0.34（2026-03-26）起 eframe 默认渲染器改为 wgpu，0.36 升 wgpu 30（一手）。https://github.com/emilk/egui/blob/main/crates/egui-wgpu/CHANGELOG.md
- **IME**：0.34 "Much improved IME"（PR #7967，在 Windows/macOS/Linux 上测了搜狗、微信输入法、Rime、fcitx5 等中文输入法），0.35 改了 IME 组字显示（一手）。https://github.com/emilk/egui/pull/7967
- **多窗口**：0.24 起支持多 viewport（原生多窗口）（一手 CHANGELOG）。
- **无障碍**：AccessKit（一手：0.35 的 inspection 协议读的就是 accesskit 树）。
- **平台**：桌面三平台稳定；Android/iOS 能跑但不是主场（推测；CHANGELOG 有 Android/iOS 挂起保存状态的修复）。
- **成熟度**：0.34（2026-03-26）、0.35（06-25）、0.36（08-05）、0.37（10-15）；由 Rerun 公司赞助维护；Rerun Viewer 是知名生产应用（一手 README/CHANGELOG）。
- **许可证**：MIT/Apache-2.0。
- **短板**（推测）：立即模式 UI，复杂动效、精致排版、设计稿还原能力明显弱于 Flutter/QML/Slint；API 每个小版本都有破坏性变更（如 0.34 把 `App::update` 拆成 `logic`/`ui`）。适合做会话窗口内的工具栏/调试面板，做"现代化重设计"的整个客户端偏吃力。

## 7. Iced —— 视频过关，仍是 0.x

- **视频**：`iced::widget::shader` + 自定义 `Primitive`（`prepare` 拿到 `wgpu::Device/Queue`，`draw`/`render` 往渲染通道里画）（一手 docs.rs）。https://docs.rs/iced/latest/iced/widget/shader/trait.Primitive.html
- 社区 iced_video_player 用这条路把 YUV 平面上传成 wgpu 纹理再 shader 转色（旁证）。https://github.com/jazzfool/iced_video_player
- **版本**：0.14.0（2025-12-07）是最新正式版，加入 IME 支持、响应式渲染等；0.15 里程碑 91% 完成，无障碍（#1849）仍是 WIP draft（一手）。
  - https://github.com/iced-rs/iced/releases/tag/0.14.0
  - https://github.com/iced-rs/iced/milestone/26
- 发版节奏：一年左右一个小版本，基本由 hecrj 一人主导；System76 的 COSMIC 桌面用的是 iced 的 fork（推测/旁证，本次未抓 COSMIC 一手页面）。
- **平台**：桌面三平台；没有官方移动端（推测）。
- **许可证**：MIT。
- **短板**：无障碍还没合入主线，移动端缺席，对五平台目标不合适。

## 8. GPUI（Zed）—— 官方版视频不过关

- **视频**：官方 `surface()` 元素只有 macOS `CVPixelBuffer` 一个来源；其他平台的视频（Zed 自己的屏幕共享）走 `RenderImage`，每帧进 sprite 图集重新上传（一手：源码）。
  - https://docs.rs/gpui/latest/src/gpui/elements/surface.rs.html
  - https://github.com/zed-industries/zed/blob/c958a12b/crates/livekit_client/src/remote_video_track_view.rs
- 社区 fork gpui-ce 给 Linux 加了 wgpu 纹理来源、Windows 加了 WGC 捕获帧来源（一手：fork 源码，但 fork 本身是社区维护）。https://docs.rs/gpui-ce/latest/src/gpui/elements/surface.rs.html
- **发布形态**：crates.io 上官方 `gpui` 停在 0.2.2（2025-10-22），之后一整年没有官方版本；社区出现 gpui-unofficial、gpui-ce、gpui-kit 等多个 fork 分别重新发布（一手：crates.io 页面）。
  - https://crates.io/crates/gpui
  - https://crates.io/crates/gpui-unofficial
- README 仍写"pre-1.0、版本之间常有破坏性变更"（一手）。https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md
- **平台**：macOS（Metal）、Windows（Win32+DirectWrite）、Linux（Wayland/X11）；无移动端（一手 README）。
- **许可证**：Apache-2.0。
- 结论：Zed 本身证明了它的 UI 质量，但对外分发形态混乱、视频路径不完整、无移动端，不推荐。

## 9. Dioxus（含 Blitz 原生渲染器）—— 有条件

- **两种渲染形态**：dioxus-desktop 走 WebView（wry，和 Tauri 一样的视频问题）；dioxus-native 用 Blitz（Stylo 样式 + Taffy 布局 + Vello GPU 渲染）（一手）。https://dioxuslabs.com/blog/release-070/
- **视频**：dioxus-native 有 `use_wgpu` / `CustomPaintSource` / 自定义 widget，能把自己的 wgpu 纹理注册成资源画进页面，官方有 wgpu-texture 示例（一手）。
  - https://docs.rs/dioxus-native/latest/dioxus_native/fn.use_wgpu.html
  - https://github.com/DioxusLabs/dioxus/blob/c64415c0/examples/10-integrations/wgpu-texture/src/main.rs
- **成熟度**：0.7.0（2025-10-31）到 0.7.10（2026-07-30），0.8.0-alpha.3（2026-10-16）；官方自己说 Blitz "仍是 work in progress，还没关注性能"（一手）。https://crates.io/crates/dioxus-native
- `use_wgpu` 在 iOS 模拟器不可用（一手 docs.rs 标注）。
- 许可证 MIT/Apache-2.0；维护方 DioxusLabs（有融资的公司）。
- 结论：技术方向对口（HTML/CSS 写界面 + wgpu 视频同一棵树），但 Blitz 还没到生产级；作为 2027 年再评估的观察对象更合适（推测）。

## 10. Compose Multiplatform —— 有条件，不推荐

- **视频**：没有官方外部纹理 API。社区项目 open-ani/mediamp 在 2026-07 做到了 Windows（D3D11 共享纹理→Skia D3D12）和 macOS（IOSurface→Metal）零拷贝，4K 约 240fps，但要靠反射 Skiko 内部对象（`SkiaLayer.getRedrawer$skiko()` 等），升级 Compose 时要重新核对（旁证）。
  - https://github.com/open-ani/mediamp/commit/94f50381933e8002b2084a5a7bebaf8de54d6e18
  - https://github.com/open-ani/mediamp/tree/main/mediamp-mpv-demo
- **Rust 互操作**：桌面跑在 JVM 上，Rust 只能经 JNI（或 UniFFI 生成 Kotlin 绑定）；等于多一层运行时 + 打包 JRE（推测）。
- **版本**：1.10.0（2026-01-13）、1.11.0（2026-05-13）、兼容表里已有 1.12.2；Windows 默认 Skia D3D12 后端（旁证 mediamp 提交说明）；支持 Android/iOS/macOS/Windows/Linux/Web（一手）。
  - https://kotlinlang.org/docs/multiplatform/compose-compatibility-and-versioning.html
  - https://github.com/JetBrains/compose-multiplatform/releases/tag/v1.11.0
- 许可证 Apache-2.0；维护方 JetBrains；中文 IME 在 1.11 还在修拼音组字问题（一手 release notes）。
- 结论：语言栈从 Dart 换成 Kotlin+JVM，对一个 Rust 引擎项目没有净收益（推测）。

## 12. 横向小结（按关键维度，列表形式）

视频上屏：
- 原生 D3D11/Metal/Vulkan 纹理直接导入：Qt/QML（官方，最全）、Flutter（Windows D3D11/DXGI 官方；macOS CVPixelBuffer）。
- wgpu 纹理导入（需同一 device）：Slint（unstable feature）、egui、Iced、Dioxus Native（预发布）。
- 只能 CPU 上传或绕道：GPUI 官方（非 macOS）、Tauri、Compose（官方层面）。

多窗口：
- 成熟：Qt、egui（viewport）、Iced、Tauri、Slint（推测）。
- Flutter：官方 API 实验中，stable 靠一窗一 engine 的插件。

移动端（Android+iOS 都稳定）：
- Flutter、Qt、Compose、Tauri v2 稳定；Slint Android 稳定、iOS 打磨中；egui/Iced/GPUI 基本无。

Rust 互操作成本（低到高）：
- Slint / egui / Iced / GPUI / Dioxus（纯 Rust）< Tauri（Rust 后端 + JS 前端）< Flutter（frb 代码生成 + Dart）< Qt（cxx-qt + C++ + QML）< Compose（JNI + JVM）。

许可证与 AGPL：
- 全部候选都能和 AGPL-3.0 一起分发：MIT/Apache/BSD（Flutter、egui、Iced、GPUI、Dioxus、Tauri、Compose、cxx-qt）、GPLv3（Slint 开源版）、LGPLv3/GPL（Qt）。

## 13. 同类产品的界面技术（旁证）

- **Moonlight（PC）**：Qt 6/QML 做主界面，SDL 处理串流窗口与输入，FFmpeg 解码 + D3D11VA/VAAPI/VideoToolbox/Vulkan(libplacebo) 渲染。一手：https://github.com/moonlight-stream/moonlight-qt （"SDL 单独开串流窗口"这一点来自对源码目录的了解，未在本次逐文件确认，算推测）。
- **Parsec**：早期 wxWidgets → 2017 年 Electron → 约 2019 年重写成原生、"渲染视频的同一套技术也渲染 UI"；最近 changelog 又"为 Free/Warp 用户重新启用 web 版 UI"。一手：https://parsec.app/blog/ushering-a-new-era-of-parsec-the-next-iteration-of-our-cross-platform-application-a692018f8095 、https://parsec.app/changelog
- **AnyDesk**：C++ 客户端（服务端 Erlang），UI 工具包未公开。旁证：Wikidata / SourceForge；官方 https://anydesk.com/en/performance 只说服务端用 Erlang。
- **NoMachine**：闭源，未找到官方说明；仅有一篇非官方文章称基于 Qt（旁证，可信度低）。https://www.sflorg.com/2026/05/rev05172601.html
- **Chrome Remote Desktop**：客户端是 remotedesktop.google.com 网页（WebRTC），主机端原生。一手：https://support.google.com/chrome/a/answer/16364503
- **Tailscale 客户端**：Windows 托盘 GUI 用 Go + lxn/walk（Tailscale 自维护 fork）；macOS/iOS/Windows 的 GUI 外壳闭源。一手：https://archive.fosdem.org/2021/schedule/event/gotailscale/attachments/slides/4651/export/events/attachments/gotailscale/slides/4651/go_at_tailscale_bradfitz_2021.pdf 、https://pkg.go.dev/github.com/tailscale/walk （macOS 用 SwiftUI 未找到证据，不下结论）。
- **Sunshine Web UI**：Vue 3 + Vite + Bootstrap 5，源码在 `src_assets/common/assets/web`，由内置 HTTPS 服务（端口 47990）提供。旁证：DeepWiki https://deepwiki.com/LizardByte/Sunshine/3.2-web-ui-architecture （仓库 https://github.com/lizardbyte/sunshine 为一手入口，本次未逐文件核对）。

规律（推测）：专做低延迟串流的产品（Moonlight、Parsec）都把"视频窗口"做成原生 GPU 渲染，界面框架要么是 Qt，要么干脆自绘；Web UI 只用于管理面（Sunshine、CRD、Parsec 的部分界面）。

## 14. 需要主会话/用户拍板的方向性问题

1. **留 Flutter 还是换**。若留：先评估把上游的 3.24.5 升到 3.47+（Impeller + 外部纹理回归）还是暂钉旧版只改 UI 层；多窗口继续用 `desktop_multi_window`，等官方 API 进 stable。若换：候选收敛到 Qt/QML 与 Slint 二选一。
2. **移动端是不是第一期目标**。如果第一期只做桌面，Slint/egui/Iced 的移动端短板可以先不计；如果要同时出 Android/iOS，Flutter 和 Qt 优势明显。
3. **能否接受"Rust + C++ + QML"三语言栈**（Qt 路线的真实成本），还是坚持纯 Rust UI（Slint 路线，代价是依赖 `unstable-wgpu-NN` feature 和 iOS 尚在打磨）。
4. **是否接受混合方案**：会话窗口用原生 GPU 渲染（Slint/egui/wgpu），连接管理/设置等窗口用另一套（Flutter 或 Tauri）。体验和维护成本都要权衡，我倾向不混（推测）。
5. 是否需要我对 1~2 个入围框架做一次最小原型实测（1080p60/4K60 RGBA 上传 + D3D11 共享纹理导入，量 CPU/GPU 占用和延迟），用数据代替文档推断。
