## 0. 一句话结论

引擎和 UI 之间**确实有一层 UI 无关的 Rust 接口**：`trait InvokeUiSession`（引擎回调 UI）+ `ui_interface.rs` / `ui_session_interface.rs` / `ui_cm_interface.rs`（UI 调引擎）。Sciter 和 Flutter 两套 UI 都实现了这层接口，这就是"引擎与 UI 可分离"的直接证据【读码】。但 Flutter 侧并不"薄"：登录、地址簿、设备组的 HTTP 请求，文件传输队列，多窗口编排，键盘模式切换的大量逻辑都写在 Dart 里（`flutter/lib` 共 138 个文件、78,499 行）。另外，引擎内部有约 20 处 `#[cfg(feature="flutter")]` 下直接调用 `crate::flutter::*` 的耦合点。

## 1. UI 怎么调用引擎

### 1.1 flutter_rust_bridge 的暴露面
- 版本：`Cargo.toml` 写死 `flutter_rust_bridge = "=1.80"`，`flutter/pubspec.yaml` 用 `flutter_rust_bridge: "1.80.1"`【读码】。这是 **v1 老版本**（现在主线是 v2，两版 API 和 codegen 不兼容）。
- codegen：`flutter_rust_bridge_codegen --rust-input ./src/flutter_ffi.rs --dart-output ./flutter/lib/generated_bridge.dart --c-output ./flutter/macos/Runner/bridge_generated.h`（出处：`flutter/run.sh`、`build.py:200`、`.github/workflows/bridge.yml:103`），codegen 本身也锁 `--version 1.80.1 --features uuid`。生成的 `generated_bridge.dart` 和 `src/bridge_generated.rs` 不入库，在 CI 的 `bridge.yml` 里生成【读码】。上游 `AGENTS.md:78` 明确写了"不要在本地跑 codegen，版本难配"。
- `src/flutter_ffi.rs` 共 3,116 行，**顶层 `pub fn` 317 个**（口径：`grep -c '^pub fn' src/flutter_ffi.rs`）。按前缀分类（口径：`grep -o '^pub fn [a-z_0-9]*' | awk -F_ '{print $1}' | sort | uniq -c`）：

| 前缀 | 数量 | 内容 |
|---|---|---|
| `main_*` | 151 | 全局：配置读写（`main_get_*` 51、`main_set_*` 17）、账号和 2FA、peer 列表和地址簿缓存、LAN 发现、安装和服务控制、HTTP 代理请求（`main_http_request`）、WOL 等 |
| `session_*` | 112 | 单个远程会话：建连、键鼠输入、显示切换、画质、文件传输、聊天、终端、录屏、纹理注册 |
| `cm_*` | 18 | 被控端连接管理窗口（Connection Manager）：授权、切权限、断开 |
| 其他 | 36 | `is_*` 12、`install_*` 5、`get_*`/`set_*`、`translate`、`start_global_event_stream` 等 |

- Dart 侧调用面：`bind.xxx` 调用点 1,042 处，用到不同函数 292 个（口径：`grep -rho 'bind\.[a-zA-Z0-9]*' flutter/lib | sort -u | wc -l`）。分布：models 278、common（含 `common.dart`）322、desktop 318、mobile 110。也就是说**一大半 FFI 调用直接写在页面和控件里**，不只在 models 里【读码】。

### 1.2 Rust 往 Flutter 推事件
两条通道，都基于 flutter_rust_bridge 的 `StreamSink`【读码】：
1. **全局事件流**：`rustdesk@bd92623:src/flutter.rs` 的 `GLOBAL_EVENT_STREAM: HashMap<String, StreamSink<String>>`，按 app type（main / cm / 各子窗口）注册，`fn start_global_event_stream`、`fn push_global_event(channel, json)`。内容是 JSON 字符串。
2. **会话事件流**：每个会话一个 `StreamSink<EventToUI>`，由 `session_start` 返回给 Dart（`flutter/lib/models/model.dart:4208` `bind.sessionStart`）。`src/flutter_ffi.rs:95` `enum EventToUI { Event(String), Rgba(usize), Texture(usize, bool), ... }`。普通事件走 `FlutterHandler::push_event_`（`src/flutter.rs:591`），把 `name` 和字段序列化成 JSON；Dart 端在 `FfiModel.startEventListener`（`model.dart:331`）里用约 44 个 `if (name == '...')` 分支分发（口径：`grep -c "if (name == '\|} else if (name == '" model.dart`）。

### 1.3 视频帧怎么交给 Flutter（关键）
`src/flutter.rs` 的 `struct VideoRenderer` 有三条路径【读码】：
- **CPU 纹理（桌面默认）**：Dart 用插件 `texture_rgba_renderer`（rustdesk-org fork）建 Flutter 外部纹理，把原生指针通过 `bind.sessionRegisterPixelbufferTexture` 交给 Rust（`flutter/lib/models/desktop_render_texture.dart:30-35`）。Rust 用 `libloading` 直接打开插件动态库（Windows `texture_rgba_renderer_plugin.dll`、Linux `libtexture_rgba_renderer_plugin.so`、macOS `open_self`），拿到 `FlutterRgbaRendererPluginOnRgba` 符号，在解码线程里把 RGBA 直接写进纹理（`VideoRenderer::on_rgba`，`flutter.rs:480`），再推 `EventToUI::Texture(display,false)`。**帧数据不经过 Dart**。
- **GPU 纹理（仅 Windows + `vram` feature）**：加载 `flutter_gpu_texture_renderer_plugin.dll`，调用 `FlutterGpuTextureRendererPluginCApiSetTexture`，把 D3D11 纹理交给插件（`VideoRenderer::on_texture`，`flutter.rs:529`）。硬解出来的帧零拷贝上屏。
- **软渲染（Android/iOS 固定走这条，桌面可选）**：Rust 把 RGBA 放在 `display_rgbas` 里，推 `EventToUI::Rgba(display)`。Dart 通过 `session_get_rgba` 读指针，`decodeImageFromPixels` 生成 Image，再 `nextRgba` 释放（`model.dart:1963-1981`）。
- 开关：`ui_interface.rs:181` `fn use_texture_render()`：Android/iOS 恒为 false；Linux 默认开；macOS 默认关（选项 `Y` 才开）；Windows 视系统版本而定。

这说明**渲染路径和 Flutter 插件 ABI 直接绑定**：换 UI 技术栈时，`VideoRenderer` 要重写成新的上屏方式。

## 2. UI 无关共享层与 Sciter 旧 UI

- **接口 trait**：`rustdesk@bd92623:src/ui_session_interface.rs:1712` `pub trait InvokeUiSession`，大约 60 个回调（`on_rgba`、`set_cursor_data`、`set_display`、`msgbox`、`job_progress`、`update_folder_files`、`on_voice_call_*`……）。会话核心 `pub struct Session<T: InvokeUiSession>`（同文件 `:61`）和收发循环 `pub struct Remote<T: InvokeUiSession>`（`src/client/io_loop.rs:74`）都对 UI 做了泛型【读码】。
- **实现方**：`src/flutter.rs:673` `impl InvokeUiSession for FlutterHandler`；`src/ui/remote.rs:123` `impl InvokeUiSession for SciterHandler`。被控端 CM 窗口同理：`src/flutter.rs:1522` 和 `src/ui/cm.rs:19` 都 `impl InvokeUiCM`【读码】。
- **UI 调引擎的共享函数**：`src/ui_interface.rs` 有 114 个顶层 `pub fn`（1,770 行），`src/ui_cm_interface.rs` 有 20 个，`Session<T>` 有 116 个 `pub fn` 方法。`flutter_ffi.rs` 和 `src/ui.rs` 都是对这些函数的薄包装【读码】。不过 `ui_interface.rs` 里有 59 处 `feature = "flutter"`，`ui_session_interface.rs` 有 19 处，说明这层"共享"并不完全中立。
- **Sciter 还活着**：`src/lib.rs:26-31` 在非 android/ios 且**没开 `flutter` feature** 时编译 `pub mod ui`；`src/main.rs` 在同样条件下走 `ui::start`。`sciter-rs` 是桌面平台的非可选依赖（`Cargo.toml` 第 100 行左右）。CI 仍有 `build-for-windows-sciter` 任务（`.github/workflows/flutter-build.yml:546`），产出 `rustdesk-*-x86-sciter.exe`，而且为了 Sciter ABI 把 Rust 工具链钉在 1.75（同文件 `:24`）【读码】。`src/ui/` 下是 `.tis`/`.html`/`.css` 文件，加上 `ui.rs` 878 行。
- 结论：**同一个引擎由两套 UI 共用**，分离在架构上成立。实际依据是 trait 加函数层，不是一个独立 crate；`flutter.rs`（2,415 行）本身也承担了一部分 UI 无关的胶水职责（见 §3.2）。

### 3.2 `flutter.rs` 里藏着的非 UI 胶水【读码】
`src/flutter.rs` 的 `pub mod sessions`（`:2039`）是**会话注册表**（session_id 到 Session、peer 到多个窗口、`has_sessions_running`、`close_all_sessions`、`query_onlines`）。跨会话剪贴板同步 `send_clipboard_msg_impl` 也在这里。引擎（`client.rs`、`io_loop.rs`）回头调用这些函数。换 UI 时这些要么抽到中立模块，要么在新 UI 的 handler 里重写一遍。

### 3.3 进程模型【读码】
桌面端是同一个可执行文件，按参数分角色：`--server`/`--service`（被控端引擎，无界面）、`--tray`、`--cm`（被控端连接管理窗口，Flutter）、主界面和 `--connect` 等（控制端，Flutter）。`src/core_main.rs:367-765`。Windows 下 Flutter runner（`flutter/windows/runner/main.cpp:26-54`）`LoadLibrary("librustdesk.dll")` 后调用 `rustdesk_core_main_args`（`src/flutter.rs:151`）。Rust 先处理 `--server` 这类参数，返回 null 时进程就不启动 Flutter。**被控端核心服务本身不依赖 UI**，只有 CM 窗口要 UI。

## 4. Flutter 端除了界面还承担了什么

总规模：`flutter/lib` 138 个 `.dart` 文件，78,499 行（口径：`find flutter/lib -name '*.dart' | xargs cat | wc -l`）。

| 目录 | 文件 / 行数 | 内容 |
|---|---|---|
| `models/` | 32 / 19,684 | 状态和业务逻辑 |
| `desktop/` | 36 / 22,860 | 桌面页面、工具栏、标签页、设置页 |
| `common/`（不含 `common.dart`） | 30 / 16,270 | 其中 `widgets/` 27 / 15,540（地址簿、对话框、peer 卡片、登录、通用工具栏） |
| `mobile/` | 17 / 10,445 | 移动端页面（含 Android 被控端界面） |

| `web/`、`utils/`、`native/` | 20 / 3,636 | Web 版 JS 桥、多窗口管理、HTTP 封装 |

### 4.1 models 里的业务逻辑【读码】
- `model.dart` 4,663 行：`FfiModel`（事件分发、peer info、显示器、权限）、`ImageModel`（软渲染）、`CursorModel`（光标图像解码和缓存）、`CanvasModel`（缩放、滚动、视口坐标换算）、`QualityMonitorModel`、`FFI` 会话聚合。直接 import `common/widgets/dialog.dart`、`peers_view.dart`、`desktop_multi_window`，调用 msgbox/dialog 约 59 处。**models 和界面耦合在一起，不是干净的 MVVM**。
- `input_model.dart` 2,482 行 + `relative_mouse_model.dart` 1,061 + `input_modifier_utils.dart` 201 + `shortcut_model.dart` 669：鼠标坐标换算、滚轮、触控手势、修饰键状态补偿、相对鼠标模式（游戏）、快捷键。
- `file_model.dart` 2,210 行 + `cm_file_model.dart` 328：文件管理器双栏状态、**传输任务队列**、覆盖确认、断点续传。Rust 只提供 `session_read_remote_dir`、`session_send_files` 这类原语。
- `ab_model.dart` 2,031 行、`group_model.dart` 378、`user_model.dart` 265：**地址簿、设备组、登录全部是 Dart 直接调 HTTP**（`/api/ab/*`、`/api/device-group/accessible`、`/api/users`、`/api/peers`、`/api/login`、`/api/currentUser`、`/api/logout`、`/api/login-options`）。走 `utils/http_service.dart`：默认用 Dart 的 `http` 包，设了代理或打开 `enable-flutter-http-on-rust` 时才转给 Rust 的 `main_http_request` 代发。
- `server_model.dart` 941：被控端状态（Android 被控、桌面 CM）。`chat_model.dart` 622，`terminal_*` 约 1,800 行（终端会话和鼠标、剪贴板处理）。

### 4.2 键盘输入的分工【读码】
- 桌面端在"映射/翻译"模式下，真正抓键的是 **Rust 的 rdev 全局 grab**（`src/keyboard.rs` `start_grab_loop`、`client::change_grab_status`）。Dart 只在鼠标进出远程画面时调用 `session_enter_or_leave(SyncReturn)`（`flutter_ffi.rs:658`）切换 grab 所有权。
- 其他情况（传统模式、移动端、Web）由 Dart 捕获 `RawKeyEvent`/`KeyEvent`，再通过 `session_handle_flutter_key_event`（`usb_hid` + 字符 + lock_modes）或 `session_handle_flutter_raw_key_event`（平台码 + 位置码）交给 Rust 翻译（`flutter_ffi.rs:612`、`:632`）。`input_model.dart` 里还有大量修饰键补偿逻辑（`lastLShiftKeyEvent` 等）。
- 含义：桌面键盘的核心能力在 Rust 里，**新 UI 不必自己实现全局抓键**，但要在获得和失去焦点时正确调用 enter/leave，并在非 grab 模式下提供平台原始键码。

### 4.3 多窗口【读码】
- 用 rustdesk-org fork 的 `desktop_multi_window`：每个远程、文件传输、端口转发、终端、摄像头窗口都是同一进程里的**独立 Flutter engine**，`main.dart:50` 按 `multi_window <id> <json>` 参数分发。18 个 dart 文件引用这个插件，`utils/multi_window_manager.dart` 581 行负责编排。
- 窗口之间通过插件的 method channel 通信。Rust 侧按 app type 区分全局事件流，并用 `sessions` 注册表支持"同一个 peer 开多个窗口"（`session_add_existed`、`is_multi_ui_session`）。
- 另外用了 `window_manager`（fork）、`flutter_custom_cursor`（fork）、`uni_links`。

### 4.4 换 UI 时要重新实现的规模【推测，基于上面的行数】
- 纯界面（desktop + mobile + common/widgets）：约 49k 行。
- 业务逻辑（models + http_service + multi_window_manager + common.dart 的一部分）：约 22–25k 行，其中输入（约 4.4k）、文件传输（约 2.5k）、地址簿/账号/设备组（约 2.7k）、会话和画布（约 4.7k）是核心。
- 如果新 UI 不用 Dart，这 ~22k 行业务逻辑要用新语言重写，或者先下沉到 Rust。

## 5. 移动端

- **同一套 Flutter + FFI**【读码】：`src/lib.rs:38-43` 在 android/ios 下无条件编译 `flutter`/`flutter_ffi`/`bridge_generated`；`main.rs` 也一样。iOS 只能做控制端（`src/lib.rs` 在 iOS 下不编译 `server`、`rendezvous_mediator`、`ipc`），原生部分只有 `AppDelegate.swift` 19 行。
- **Android 被控端有大量 Kotlin**【读码】：`flutter/android/app/src/main/kotlin` 下共 4,191 行（口径：`find flutter/android -name '*.kt' -o -name '*.java' | xargs wc -l`）。
  - `MainService.kt` 1,003：前台服务、MediaProjection 抓屏，通过 JNI `onVideoFrameUpdate(ByteBuffer)` 把帧交给 Rust 编码；`AudioRecordHandle.kt` 284 负责音频采集。
  - `InputService.kt` 761：AccessibilityService 注入触控和按键（Android 上没有 enigo）。
  - `MainActivity.kt` 1,021：Flutter 和原生之间的 `MethodChannel("mChannel")`，权限申请。
  - `FloatingWindowService.kt`、`RdClipboardManager.kt`、`KeyboardKeyEventMapper.kt`、`BootReceiver.kt` 等。
  - JNI 入口：`flutter/android/.../ffi.kt`（`System.loadLibrary("rustdesk")`，约 10 个 `external fun`）对应 `libs/scrap/src/android/ffi.rs`（8 个 `Java_` 符号）。
- 也就是说 Android 被控端的抓屏和输入**不在 libs/scrap 和 enigo 里，而在 Kotlin 里**。不管换不换 UI，这部分都要保留。

## 6. 结论：换 UI 的几条路

### 6.1 不管哪条路，引擎能原样保留的部分【读码 + 推测】
`libs/*`（约 44k 行）、`src/server/`、`src/client*`、`rendezvous_mediator`、`keyboard`、`platform`、`ipc`、`ui_interface`/`ui_session_interface`/`ui_cm_interface` 可以原样保留，合计远超 10 万行。要改的集中在三处：
1. `src/flutter.rs`（2,415）+ `src/flutter_ffi.rs`（3,116）：换成新 UI 的 handler 和绑定层。
2. 引擎里约 20 处 `crate::flutter::*` 直接调用（集中在 `client.rs`、`client/io_loop.rs`、`server/connection.rs`、`server/dbus.rs`、`rendezvous_mediator.rs:246`、`common.rs:1119`）：先把 `sessions` 注册表、剪贴板同步、`push_global_event` 抽成中立模块（例如 `ui_bridge`），引擎改为调中立接口。【推测：工作量在几百行量级】
3. `VideoRenderer`：换成新 UI 的上屏方式。

### 6.2 新 UI 必须提供的能力和难点

| 能力 | 现状 | Flutter 新界面 | Tauri + Web | 原生（Win32/WinUI、SwiftUI、GTK 等） |
|---|---|---|---|---|
| 视频上屏 | 插件外部纹理，Rust 直写；Windows 可走 D3D11 零拷贝 | 原样复用 | **最难**：WebView 拿不到原生纹理。要么把 RGBA 经 IPC 送进 WebView（1080p60 约 500MB/s，不现实），要么把编码帧送进 WebView 用 WebCodecs 解码（上游 Web 客户端 `web_video_frame_queue.dart` 就是这个思路，但那样就绕开了 Rust 的硬解和 vram 路径），要么在 WebView 下面叠一个原生子窗口渲染（各平台分别实现）【推测】 | 每个平台各写一个渲染器（D3D11/Metal/GL），能直接拿 vram 纹理，性能最好、代码量最大【推测】 |
| 键鼠捕获 | 桌面 grab 在 Rust；鼠标坐标换算和手势在 Dart | 复用 `input_model` | 键盘 grab 仍由 Rust 负责，WebView 只报焦点；但鼠标事件要从 DOM 映射，相对鼠标（pointer lock）、修饰键补偿要重写；WebView 会吞掉部分快捷键（Win/Cmd、Alt+Tab 之类），要靠 Rust grab 兜住【推测】 | 直接拿原生事件，最准确 |
| 剪贴板 | 文本和图片在 Rust（`src/clipboard.rs`、`libs/clipboard`），Dart 只发开关 | 复用 | 基本复用 Rust | 基本复用 Rust |
| 多窗口 | `desktop_multi_window`，一窗一 engine | 复用 | Tauri 原生支持多窗口，但每个窗口一个 WebView，内存开销不小【推测】 | 原生 |
| 账号/地址簿/设备组 | **Dart 直接发 HTTP** | 复用（Porta 本来就要改这部分 API） | 用 TS 重写，或下沉到 Rust | 下沉到 Rust |
| 文件传输界面 | 队列和状态在 Dart | 复用 | 重写 | 重写 |
| 移动端 | Flutter 一套 | 一套代码覆盖 | Tauri 2 的移动端不成熟；Android 被控端的 Kotlin 还要和新 UI 接起来【推测】 | 每个平台各写一套 |
| 被控端 CM 窗口 | Flutter `--cm` | 复用 | 重写（小） | 重写（小） |

### 6.3 推荐评估："保留 Flutter，重写界面层和样式，保留 models"
- 保留：Rust 全部、`flutter_ffi.rs`、`models/`（19.7k）、`utils/`、`common/hbbs`、`desktop_render_texture.dart`、多窗口机制、Android Kotlin。
- 重写：`desktop/`（22.9k）、`mobile/`（10.4k）、`common/widgets/`（15.5k）、`common.dart` 里和主题相关的部分，合计约 **45–50k 行 Dart 界面代码**【推测：按行数估计】。
- 难点：
  1. models 不干净：`model.dart` 直接 import `dialog.dart`、`peers_view.dart`，约 59 处 msgbox/dialog 调用；models 里还有 10 个文件 import `material.dart`。重写界面时要先把"model 弹对话框"改成"model 发出状态，界面决定怎么显示"，否则新旧界面会互相牵连。
  2. 一大半 `bind.*` 调用（common 322 + desktop 318 + mobile 110，models 只有 278）写在页面里。重写界面时这些调用要么搬进 models，要么在新页面里重新接一遍，容易漏掉功能。
  3. 和上游同步：`flutter/lib` 是上游改动最频繁的目录之一【推测】。界面层整体重写后，上游的界面修复基本没法 cherry-pick，只能靠 Rust 和 models 跟进。
  4. flutter_rust_bridge 停在 v1.80，Flutter SDK 版本也被这些 fork 插件锁着。现代化 UI 想用的新版 Flutter 特性可能会撞上这些限制【推测，需要单独核对 `pubspec.lock` 和 CI 里的 Flutter 版本】。
- 好处：渲染、多窗口、移动端、Android 被控端全部零改动；工作量集中在 Dart 界面，可以按页面逐步替换。
- 工作量判断【推测】：在四条路里成本最低、风险最小，量级约为"Tauri + Web"的三分之一到一半，因为 Tauri 那条路除了界面，还要重写约 22k 行业务逻辑，外加视频上屏和移动端。

### 6.4 明确不建议的做法
- 不建议继续用 Sciter：它绑定 Rust 1.75、只剩 Windows x86 一个 CI 产物，上游已经事实上弃用。但 `src/ui/` 可以当作"第二个 `InvokeUiSession` 实现"的最小参考样例（`ui/remote.rs`）。
