# 新界面 M8：切换的拆法

2026-11-06 起草，待维护者定 §8。

- 依据：`03-实施方案.md`（下称"03"）§1.5、§1.7、§1.8、§5.2"M8 切换"、§7.1~§7.3、§8.5~§8.8；`01-内容与逻辑说明.md`（下称"01"）P1 区块 B；`冒烟清单.md`；`docs/第二期客户端冒烟清单.md`。读码基于 leapgate-client main `7c8490a1e`，两路读码（安装、升级、卸载和便携打包一路；命令行和链接、构建脚本、验收清单一路）。
- M8 之后，发布的 `leapgate.exe` 是新界面。exe 名、dll 名、安装路径、服务名都不变，已安装的覆盖安装即可（03 §7.2）。第三轮（TCP 隧道 / RDP、终端、摄像头、安装页）和 M7b 都在切换之后。
- 这份文档写 M8 要做什么、谁做、怎么验收、哪些不做，以及要维护者定的十条。确认后决定回写进 03、01，动手的细节写进 `client/LEAPGATE.md` 新一节 §10.16。

## 要点

1. 03 原文说切换"只改构建脚本的默认值"。读码后看，安装版那一套（服务拉起 `--server`、`--server` 拉起新界面的 CM、托盘"打开"、登录后起托盘）新界面都已经接得住，但有三处会挡住发布：
   - **`--install` 被吞掉**：上游便携打包默认把包名叫 `leapgate-‹版本›-install.exe`，双击后打包器给界面传 `--install`，新界面收到就退出，用户什么都看不到。
   - **主页没有"安装""升级"两张提示卡**：M2b 定的是 M8 之前不显示；上游这两个按钮走的也是 `--install`，新界面不能照搬。
   - **链接和 `--file-transfer` 打不开文件传输**：M7a 做了文件传输视图，`handleLaunchArgs` 还没接上，已在运行时没有任何反应。
2. 另有几处要定的：
   - 便携打包两个界面都没做；
   - 默认服务器从来没注入过；
   - 卸载项里的版本号是上游的 1.5.1，不是 Leapgate 的 0.4.0；
   - 应用图标还是第二期的占位图标，标题栏上是一个灰色方块；
   - "升级"卡比的是构建时间，不是版本号。
3. 代码量小：Rust 约 60~100 行（一个安装导出，可能加一处一行的上游挂钩），Dart 约 300~500 行加测试，构建脚本约 100 行。**大头在验收**：
   - 新界面冒烟清单要先补上 M4~M7a 几节，再全过一遍；
   - 便携版在两台端点上测，安装版、覆盖安装、卸载、链接、托盘在测试虚拟机上测；
   - 03 §8.7 第 2 段的压力项跑一次；
   - 最后做最新 stable 检查和外观检查。
4. 要定的十条在 §8，最要紧的是：
   - M8-1：两张提示卡怎么装；
   - M8-2：`--install` 和便携包名；
   - M8-4：默认服务器注不注入；
   - M8-8：切换后要用 TCP 隧道、终端、摄像头时怎么办。

### 1.2 和 03 原文不同的几处

- 03 §7.2 写"本机提示卡的'安装'直接调 Rust 现成的 `--silent-install`"。读码后不推荐：
  - `--silent-install` 会按进程名杀掉所有 `leapgate.exe`（包括发起安装的便携版主窗口）；
  - 装完只拉起托盘、不拉起界面，结果只用系统通知告知；
  - 当"升级"用时会把装在自定义路径的程序挪回默认路径。
  
  改成 Leapgate 自己的导出（M8-1）。

## 4. 几处要先说清的

### 4.1 安装、升级为什么要新导出

上游两个按钮都是"带 `--install` 重启自己，交给安装页"（`src/ui_interface.rs:101-120`），安装页在第三轮。可选的三种做法见 M8-1。推荐的新导出在界面进程里调安装，代价是它会经过上游的安装脚本：脚本先跑一遍卸载（停服务、杀进程、`rd /s /q` 删掉安装目录），再把当前 exe 所在的整个目录拷过去（`src/platform/windows.rs:1515-1526`、`:1640`、`:1775`、`:1899`）。所以新旧界面互相覆盖安装都不会留下多余的文件（旧界面多 4 个插件 dll 和一批 svg、ttf），但拷贝遇到锁住的文件会跳过，脚本杀进程没杀干净时可能新旧混装，验收专门测一次（§5.3）。

装成功后界面必须退出：否则安装好的程序启动时按窗口类名找到便携版的窗口，会把自己交过去后退出（`main.cpp:109-140`）。

### 4.2 `--install` 从哪来

三个来源（`src/common.rs:1203`、`src/core_main.rs:136-140`、`libs/portable/src/main.rs:286-309`）：exe 名以 `install.exe` 结尾；便携包名以 `install.exe` 结尾；上游的安装、升级按钮。新界面不用后者，前两者只看文件名。上游 CI 发布的包名本来就不带 `install`（`flutter-build.yml:439`），只有 `build.py` 本地打包默认带（`build.py:995`）。

新 runner 把 `--install` 当安装页、不交给已开着的窗口（`main.cpp:20`、`:161`），所以只在界面里把它当普通启动不够，要 runner 和界面一起改（M8-2 的备选）。

### 4.3 第三轮的几种会话从链接进来

Rust 把七种参数转成 `leapgate://类型/ID?…` 交给已在运行的主窗口（`src/core_main.rs:759-831`），找不到主窗口时 Dart 直接拿到原始参数。链接只在安装版上能从外部触发（URL 协议在安装时才注册，`src/platform/windows.rs:1620-1627`），地址簿"创建桌面快捷方式"生成的是 `--connect`，已经接得住。端口转发、RDP、摄像头、终端现在静默；`--terminal-admin` 只能经链接进来。

### 4.4 "升级"卡比的是构建时间

`is_installed_lower_version` 比较的是安装时写进注册表的构建时间字符串和当前程序的构建时间（`src/ui_interface.rs:565-573`），不是版本号。构建时间只在 `build.rs` 重跑时更新（主检出里现在还是 10-28），不强制刷新的话，该出现时可能不出现。

副作用：切换后保留到 M9 的旧界面便携版，如果构建时间比装着的新界面晚，会提示"升级"，点了就把安装版降回旧界面。不改旧界面（过渡期只修阻塞性问题），写进说明：用切换前编的旧界面便携版，或者别点它的"升级"。

### 4.5 装着新界面时用旧界面便携版

主 IPC 只认同一路径的 exe（`src/ipc/auth.rs:472-493`），03 §7.1 已定两个界面不同时运行。切换后要用 TCP 隧道、终端、摄像头（第三轮之前只有旧界面有），得先停掉安装版的服务和托盘，再开旧界面便携版，用完反过来。见 M8-8。

## 5. 验收

验收记录写进 `client/LEAPGATE.md` §10.5"M8"，每条写通过、不通过或未验证。

### 5.1 自动测试

- Rust：§2.2 的单测。
- Dart：两张卡的出现条件和失败态（假导出）；链接分派（`file-transfer` 打开文件传输、四种第三轮的出提示）。
- 合入前：`git diff main -- flutter/` 为空；core、app 的 analyze 基线不变。

### 5.2 便携版（两台端点，无人值守）

- 新界面冒烟清单全过一遍（补齐 M4~M7a 以后的版本），旧界面五项冒烟（Rust 改了）。
- 03 §8.7 第 2 段：会话标签开关 50 次的句柄和内存斜率；开着 UIA 客户端（原生 COM 的 IUIAutomation 轮询）反复开关会话标签和对话框；3~4 个会话标签同时开着时的 CPU、GPU 占用（V1 开着）。
- 冷启动 `--connect`：Rust 这时不在本进程里起服务（`src/core_main.rs:132-135`），看主窗口本机区的状态对不对。
- 便携包：双击后能起来，第二次双击（时间戳相同）不重解；两个界面解到同一个目录（`%LOCALAPPDATA%\leapgate`）的影响看一眼。
- 最新 stable 检查（03 §8.8）。

### 5.3 安装版（测试虚拟机，回滚快照后测，测完回滚）

- "安装"卡：便携版点"安装"，装完界面退出、安装版接手；服务、托盘、开机自启、开始菜单和桌面快捷方式、防火墙规则、卸载项（DisplayVersion 按 M8-5）。
- "升级"卡：装一份构建时间早的，再用新构建的便携版看卡片出现、点"升级"，自定义路径保留。
- 覆盖安装：先装旧界面安装版，再用新界面装上去，看目录里没有旧界面的文件、服务和 CM 是新界面的；再反过来装一次旧界面。
- 托盘"打开"能拉回隐藏的主窗口；有人连进来时弹的是新界面的 CM；交换控制方向（`src/server/connection.rs:4012`，至今没有验收记录）。
- 链接：`leapgate://ID`、`/r`、`connection/new/`、`file-transfer`，和四种第三轮的提示。
- 主页密码行"修改"先解锁（R2-Q31）。
- 卸载：删掉服务、协议、防火墙规则、卸载项、安装目录和快捷方式，留下配置和日志。
- 与原版共存（第二期冒烟清单 §6）：按 M8-10 在测试虚拟机上装一份上游原版。
- 第二期冒烟清单 §4、§5、§9 的其余各条。§1~§3 要注入了默认服务器的构建，按 M8-4 随第一期部署。

### 5.4 没法无人值守的

- 取消 UAC：测试虚拟机快照里管理员提权不弹框（`ConsentPromptBehaviorAdmin = 0`），三种失败态（取消、失败、成功）只能在维护者机器上看，写进试用说明。
- 讲述人读主页、新界面里的拖放、带修饰键的键盘：沿用试用说明里已有的条目。

### 5.5 修完复测

不通过的改完后复测对应各条；动了构建脚本就重跑便携包和安装一节。

### 5.6 最后一轮外观检查

功能验收和修复都做完后，对准备合入的提交看：两张提示卡（进行中、失败）、全局轻提示、标题栏图标，浅色深色；和 `样稿/A-P1.html` 的本机提示卡（`.pcard`）对照。

| 部分 | 行数 |
|---|---|
| Rust（含单测） | 约 60~100 |
| Dart（卡片、链接、标题栏图标） | 约 300~500，测试约 300 |
| 构建脚本 | 约 100 |
| 上游文件 | 0 处，M8-5 选改版本号时 1 处、1 行 |
| 冒烟清单补齐 | 约 300~400 行文档 |

ARB 约 10 个键（中英各一份）。验收比代码大：便携版一轮、安装版一轮、压力项、最新 stable、外观检查。

## 8. 要维护者定的

| 编号 | 问题 | 推荐 | 备选 | 理由和代价 |
|---|---|---|---|---|
| M8-1 | 两张提示卡怎么装 | 块 2 新导出（§2.2）：成功时界面退出、安装版接手；失败把原因交回卡片显示；"升级"用已安装的路径和选项；上游文件不动 | 甲：起子进程跑 `--silent-install`；乙：直接调上游 `installInstallMe` | 甲不用写 Rust，但用默认路径（当"升级"用会把自定义路径的程序挪回默认路径）、会杀掉发起安装的便携版窗口、装完没有界面、结果只有系统通知。乙失败或取消 UAC 时窗口直接消失（`src/ui_interface.rs:107-115`）。推荐约 20~40 行，代价是多一个导出 |
| M8-2 | `--install` 和便携包名 | 包名不带 `install`（`leapgate-‹版本›-x86_64.exe`，和上游 CI 一样），`--install` 在第三轮安装页之前保持退出，写进已知限制 | runner 和界面一起把 `--install` 当普通启动 | 推荐只改脚本里的包名；只有用户自己把 exe 改名成 `…install.exe` 或手动带参数才会碰到。备选要改 runner（它把 `--install` 当安装页、用另一个窗口类），第三轮做安装页时又要改回去 |
| M8-3 | 发布产物出几种 | 便携单文件 exe（`generate.py`）加发布目录的 zip | 只出 zip | 单文件 exe 是上游的发布形式，双击就用，以后分发给别人也是它；要在构建工具链里装 brotli，打包和 dpiAware 那一行要实测。只出 zip 省事，但每次要解压，第一次分发前还得补 |
| M8-4 | 默认服务器注不注入 | M8 不注入：新装的用户在设置里填服务器；脚本打印"未注入" | 注入测试服务器，或注入现网服务器 | 第一期服务端还没部署，现网是原版 hbbs，测试服务器不该成为默认值；注入的值随第一期部署一起定。代价是第二期冒烟清单 §1~§3（默认服务器那几条）这次不测 |
| M8-5 | 卸载项里的版本号 | 改成 Leapgate 的版本（0.4.0），`install_me` 里一处一行的 `leapgate::` 挂钩 | 保持上游的 1.5.1，写进已知限制 | "应用和功能"里显示的版本应和关于页、exe 版本资源一致（R2-Q32 定的是 Leapgate 版本）。代价是上游文件多一处挂钩，每次合并上游要看一眼 |
| M8-6 | 应用图标 | 继续用第二期的门形占位图标（exe、托盘已经是它），标题栏的灰方块换成同一个图标；Logo 另行设计，不挡切换 | 切换前先设计 Logo 和图标 | 03 IQ5 已接受"带着占位图标发布"；标题栏的灰方块太像没做完。备选要多一轮设计和确认 |
| M8-7 | 第三轮的几种会话从链接进来 | 发一条全局轻提示"暂不支持打开‹端口转发 / 远程桌面协议（RDP）/ 摄像头 / 终端›会话。"，不打开任何东西 | 照现在静默，只写日志 | 静默时用户以为程序坏了。提示不带"请用旧界面"这类话（产品文案不提过渡安排） |
| M8-8 | 切换后要用 TCP 隧道、终端、摄像头时 | 停掉安装版的服务和托盘，开旧界面便携版，用完再起安装版；写进说明和冒烟清单（03 §7.2 合并上游后跑"端口转发"那项也这样做） | 维护者自己的机器先不装新界面安装版，等第三轮做完 | 主 IPC 只认同一路径的 exe，两个界面不能同时跑（03 §7.1 已定）。备选不用来回切，但新界面安装版只在测试虚拟机上有人用，日常发现不了安装版的问题 |
| M8-9 | 发布构建在哪做 | 在用户目录以外建发布 worktree（例如 `C:\porta-build\src`），顺带解决"第一次给别人分发前"那条（Flutter 产物里残留本机用户路径）；删掉落后 main 几百个提交、已经没用的 `.wt/client-brand` | 继续在 `.wt/ui-m0-build` 里编 | 推荐一次性多一个 worktree 和一份编译缓存（几 GB）。备选不占空间，但产物里带本机用户路径，分发前还得换 |
| M8-10 | 与原版共存怎么测 | 在测试虚拟机上装一份上游原版 1.4.9（和 M7a 同一个安装包，从 GitHub 重新下载、核对 sha256，测完回滚快照） | 不测共存，留到第二期统一验收 | 新界面安装版第一次和原版装在同一台机器上（两边的服务、驱动、虚拟显示、托盘）。维护者日常用的两台上的原版指着现网，不碰 |
