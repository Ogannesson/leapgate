配色调整

方向 A · 当面 · 现状、微调、适度、更大胆

这一页是什么。维护者看完第二步样稿后的意见：布局、组件和 SVG 图标都满意，配色已经和谐，但有些地方不够大胆，画面显得趋同，可以多用一点颜色，改的时候不要突兀。这里把“多用一点颜色”拆成三档，加上现状共四套，放在同一组画面上换着看。挑定一套之后再同步进 A-基础和五个页面，那一步还没有做。布局、组件形状、图标、尺寸、字号都没有动，只换颜色，以及少数几处颜色出现的位置。

三档怎么分。同一批位置、同一组色相，力度逐级加大。微调只动四处，看上去几乎就是现在的样子；适度把颜色铺到本机区、设备图标、标签和会话标签上；更大胆再加深、加饱和，本机区和选中项整块上色，并多一个次强调色“梅紫”，专给“出口”。三档都从现有的色相长出来：雾青灰的底、青色的强调色、状态色的色相家族，新加的颜色按现有色板的明度和色度派生。

颜色表示什么。每处新增的颜色都带含义：身份（哪台设备、哪个人）、状态（在线、直连、经中继、未加密、出错）、所在位置（选中的导航、当前标签、展开着的菜单）、功能区（本机、出口、被控时的来访者）。说不出含义的地方没有加。

身份色（三级共用）

每台设备、每位来访者按 ID 取一个固定颜色，同一个身份到哪里都同色。七种颜色避开状态色：绿色留给在线和直连，红色留给出错，琥珀留给警告，靛蓝留给经中继，青色是强调色，梅紫是出口，这几个位置身份色一个也不占。身份色的色相落在它们之间的空档里，明度上也错开：浅色里身份实色比状态色亮一档（状态色是深而稳的字色），深色里比状态色暗一档（状态色是亮色）。三个值各有用处：实色用在顶条、头像、更大胆的图标块，上面放白字或深字；浅底用在适度的图标块，上面放身份深字；深字是浅底上的图标和灰块上的图标。文字永远用正文色，身份色不承担文字对比度。

色块上的字母是示意：实色上放 --lg-on-k（浅色白，深色近黑），浅底上放深字。令牌名 --lg-k1-s、--lg-k1-t、--lg-k1-i 分别是 k1 的实色、浅底、深字，k2 到 k7 同理。

身份色和状态色不会混

对比度

按 WCAG 2.x 相对亮度公式，用脚本（Python）读本页 CSS 里每个令牌在浏览器里的计算值算出（2026-10-29），不是从上面的表里抄的色值。带透明度的叠加色先叠在它所在的底上，再像浏览器那样把每个通道取整到 8 位，数字向下取到两位小数。标准是 AA：正文和小字 4.5:1，大字、图标、状态标记、控件轮廓 3:1。每一行是前景和底的一种搭配，行里有多个底或多个身份时取最低的那一格，前景用的是画框里那条 CSS 规则实际引用的令牌。标签颜色是用户自选的，浅底按比例掺进所在的底，所以标签文字取最差的颜色（浅色里是黑，深色里是白）。每级表后另有一条：用浏览器对本级画框里每一个文字、图标元素取计算样式再复算一遍（半透明的底先合成），数字不是从表里推出来的。

给开发的说明

  • 本机区要拆成一个块。样稿里把“本机”标题、ID、一次性密码、复制和刷新按钮、“更多访问设置”从原来的滚动区里拿出来，成为一个固定的块（类名 mine），它下面才是服务状态、被控提示和导航。现状和微调里这个块没有外观，位置和原来一模一样；适度和更大胆里它有自己的底，伸到面板的边缘。写 Flutter 时要把这一段拆成独立的组件，不再放进滚动区。这是逻辑之外的结构调整，由 coder 决定怎么拆。
  • 身份色的取法。每台设备、每位来访者按 ID 取一个固定颜色，同一个身份在卡片、会话标签、被控端小窗、出口目录里同色。取色的函数（哈希）由开发定，要求稳定、同 ID 同色；设备多于七台时撞色是正常的，所以身份色只用来帮助认出，不当唯一标识，文字永远用正文色。本页的八台设备分到六种颜色：办公室电脑和工作室绘图电脑撞色（赭黄），老王的 MacBook 和爸爸的台式机撞色（苔绿），是手工指派的，不是哈希的结果，用来看撞色时的样子：撞色的两台各有名字、状态和标签，仍然分得开。来访者李四用陶橙，画框里没有设备用它，所以左栏“正在被远程控制”的李四不会被当成哪台设备；出口页里“李四的台式机”和李四是同一个 ID，所以同色。标签没有跟着身份色走：同一张卡片上图标块的颜色和标签的颜色互不相干，已经让它们的色相错开（家里是粉，没有哪台“家里”的设备用玫红）。
  • 已有问题：深色里的经中继按钮差 0.01。A-基础的深色配色里，工具栏展开着的连接方式按钮上，“经中继”的字压在选中叠加上是 4.49:1，低于 4.5。微调把深色的中继色提亮到刚好达标（#AAB3FF 改为 #ABB4FF），适度和更大胆的深色中继色已经按各自的底重算。如果最后挑了“现状”，这一处也要补，同样改成 #ABB4FF。
  • 颜色的生成方式。身份色用 OKLCH 按色相逐色相生成，实色的明度和色度按“和每个状态色的色差 ≥ 10、对比度够用”逐个收紧，浅底按“和警告底、错误底色差 ≥ 6”收紧，深字按对浅底 ≥ 6 收紧。状态色在原色相上调高色度，明度按最深的底收紧到 4.5:1 以上。表里的色值是写进 CSS 的最终取值。
  • 标签的浅底按比例算，不逐个写。标签颜色是用户在色轮上自选的，产品里不可能给每个标签配一个浅底令牌。做法是把标签色按固定比例（适度浅色 12%、深色 16%；更大胆浅色 20%、深色 18%）掺进它所在的底，文字用正文色，Flutter 里是 Color.alphaBlend(标签色.withOpacity(比例), 底色)。这个比例是按最差的标签色（浅色里黑、深色里白）压在所有可能的底上（表面、表面2、浮层底、选中叠加）都 ≥ 4.5 定的，所以任意颜色都达标，不用再逐色检查；另用色轮上每隔 15° 取 4 档明度、3 档色度的高饱和颜色，加黑、白、三原色和灰，共 103 种逐一压在这些底上验证过，没有比最差情形更低的。共用块里标签文字现在用次要文字色，说明 §3.1 要的是正文色：挑定后同步 A-基础时，共用块的 .frame .tg 要把 color 改成 --lg-text；现状和微调没有浅底，次要文字压在表面上本来就达标，所以这两级不受影响。
  • 被控提示和信息头用固定的功能底。“正在被远程控制”和被控端小窗信息头表示的是“这是你这台机器上的事”，不是“这是谁”，所以底色固定（浅青），不跟来访者变；来访者的身份只出现在头像、会话标签顶条，更大胆再加信息头左缘、头像外圈和提示的细边。这样来访者的身份色不会撞上错误底、警告底，也不会让提示看起来像是某台设备在控制本机。
  • 尺寸有两处极小的变化。适度和更大胆里，本机区的色块上下各多出 16 像素的内边距，下面的内容整体下移 16 像素；被控端小窗的信息头底下多留 8 像素。标签的浅底小块比原来的色点高 2 像素、宽 15 像素，右对齐，不会挤到别的元素。别的位置没有变。
  • 梅紫只给“出口”。梅紫是更大胆独有的次强调色，色相取自标签色板里粉和紫之间的那一段（OKLCH 色相约 330），在色轮上和七个身份色、状态色都隔开。它的含义只有一个：这是出口功能，只出现在出口的导航项、徽标、“正在使用”卡片的左缘和页面标题上；出口页的底色不动，免得整页变成紫黑底。如果挑了适度或微调，这个颜色不出现。
