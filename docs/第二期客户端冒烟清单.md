# 第二期客户端冒烟清单

这份清单给维护者在 Windows 上手动验证新构建的 Leapgate 客户端用。每次第二期出了新构建，按顺序过一遍；第二期验收（Leapgate 客户端和原版 RustDesk 装在同一台机器上共存，并且能互相连接，见 `docs/architecture.md` 第 5 节）也按它做。每条写了怎么做和怎样算通过，没通过的条目记下现象和日志位置。

依据：`docs/research/第二期客户端/01`~`03` 的验证项，以及 `leapgate-client` 截至 `ea74616` 的改动（`libs/leapgate` 和其中注明的上游挂钩）。

## 准备

- 一台 Windows 10 或 11 的 x64 机器做主测试机。测 IPv6 直连和中继时再加一台，两台都要有 IPv6 地址。
- 一个在跑的 leapgate-server（第一期），下文写作"你的 leapgate-server 地址"和"你的公钥"，并用 `leapgate-server user add <用户名>` 建好一个测试账号。
- 原版 RustDesk 的官方安装包（当前正式版）。
- 构建前在同一个 PowerShell 会话里设好构建时注入的变量：`LEAPGATE_RENDEZVOUS_SERVER`（你的 leapgate-server 地址）、`LEAPGATE_RS_PUB_KEY`（你的公钥），可选 `LEAPGATE_API_SERVER`。不设 `LEAPGATE_RENDEZVOUS_SERVER` 编出来的是"没有内置服务器"的构建，只有第 2 节标注的两条要用它测。
- 下文路径里的"服务配置目录"指 `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\Leapgate\config`（安装后服务进程用的配置），"用户配置目录"指 `%APPDATA%\Leapgate\config`。日志在各自配置目录的上一级 `log\` 下，服务进程的日志在 `log\server\`。

## 1. 构建产物

- [ ] 按 `scripts/windows/build-client.ps1` 构建。通过：脚本最后打印绿色的"产物：…"，中途没有抛错。
- [ ] 看产物目录 `flutter\build\windows\x64\runner\Release\`。通过：有 `leapgate.exe`、`libleapgate.dll`、`flutter_windows.dll`、`data\app.so`、`dylib_virtual_display.dll`；开了 vram（默认）时还有 `flutter_gpu_texture_renderer_plugin.dll`；没有 `rustdesk.exe` 和 `librustdesk.dll`。
- [ ] 在产物目录里跑 `Get-ChildItem -Recurse -Name | Select-String rustdesk`。通过：没有输出。有输出就记下文件名，交给品牌任务判断是不是内部标识。
- [ ] 跑 `(Get-Item leapgate.exe).VersionInfo | Format-List`。通过：ProductName 是 `Leapgate`，FileDescription 是 `Leapgate Remote Desktop`，OriginalFilename 是 `leapgate.exe`，LegalCopyright 里有 "Based on RustDesk" 和上游版权行。
- [ ] 构建日志里没有"flutter\pubspec.lock 和 … 不一致"的警告。通过：没有这条警告；出现了就按警告的提示更新 `scripts/windows/` 下钉住的那份 lock。
- [ ] 在 Git Bash 里对 `leapgate.exe` 和 `libleapgate.dll` 跑 `grep -a -c "<你的 Windows 用户名>"`。通过：两个文件都是 0。`data\app.so` 和 `flutter_gpu_texture_renderer_plugin.dll` 里还会有本机用户路径，属于已知缺口（见第 10 节），这里不算失败。

## 2. 首次启动（不安装，直接运行）

- [ ] 双击产物目录里的 `leapgate.exe`（内置了服务器的构建）。通过：主窗口打开，标题是 Leapgate，几秒内显示本机 ID，状态变成就绪。
- [ ] 看主界面。通过：没有"设置服务器"一类的提示条（上游点它会打开 rustdesk.com 的定价页）。
- [ ] 看 `%APPDATA%`。通过：新建了 `%APPDATA%\Leapgate\config\`，里面有 `Leapgate.toml`、`Leapgate2.toml`；`%APPDATA%\RustDesk` 没有因为这次启动新建或改动。
- [ ] 主界面左侧的安装提示里写的是 Leapgate。通过：简体中文界面下提示文字是"将 Leapgate 安装到系统"。
- [ ] 用没有内置服务器的构建启动，等 2 分钟，看用户配置目录上一级的 `log\` 下最新的日志。通过：只出现一次 "No rendezvous server configured, waiting for one to be set"，没有每隔几秒重复的连接错误。
- [ ] 接上一条，在"设置 → 网络 → ID/中继服务器"里填你的 leapgate-server 地址和公钥，保存。通过：不用重启，几秒内日志出现 "Rendezvous server configured"，主界面显示 ID、状态就绪。

## 3. 品牌

- [ ] 看 exe 图标、任务栏图标、窗口左上角图标和托盘图标。通过：都是 Leapgate 的门形占位图标，没有 RustDesk 的标志。
- [ ] 看主界面左栏 logo 附近。通过：没有 "Powered by RustDesk" 或"由 RustDesk 提供支持"。
- [ ] 打开一个远程会话，看主窗口标签栏标题和会话窗口标题。通过：写的是 Leapgate，不是 RustDesk。
- [ ] 打开"设置 → 关于"。通过：卡片标题是"关于 Leapgate"，版权区第一行是 "Leapgate, based on RustDesk"，下面保留上游版权行。Privacy Statement 和 Website 两个链接仍指向 rustdesk.com，属于已知缺口，这里不算失败，也不要点。
- [ ] 中英文界面各浏览一遍：主界面、设置各页、远程会话工具栏、被控端的连接管理窗口、托盘菜单。通过：除关于页的版权区外，看不到 RustDesk 字样；发现了就记下位置。
- [ ] 在"设置 → 安全"里打开双重认证，用验证器 App 扫码。通过：验证器里的发行者显示 Leapgate。

## 4. 安装

- [ ] 点主界面的安装按钮进入安装页。通过：默认安装路径是 `C:\Program Files\Leapgate`；UAC 提示显示"未知发布者"（前两期不签名，属预期）。
- [ ] 安装页取消勾选远程打印机选项后安装。通过：安装完成，自动以安装版重新启动。（这期构建不带打印机驱动，见第 10 节。）
- [ ] 看安装目录。通过：`C:\Program Files\Leapgate\` 下有 `Leapgate.exe`（安装时按应用名改名）和 `libleapgate.dll`。
- [ ] 跑 `sc qc Leapgate` 和 `sc query Leapgate`。通过：服务名 `Leapgate`，显示名 `Leapgate Service`，可执行文件指向 `C:\Program Files\Leapgate\Leapgate.exe` 并带 `--service`，状态 RUNNING。
- [ ] 跑 `reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\Leapgate`。通过：`DisplayName` 是 Leapgate，`InstallLocation` 是 `C:\Program Files\Leapgate`；"设置 → 应用 → 已安装的应用"里能看到 Leapgate。
- [ ] 跑 `reg query HKCR\leapgate` 和 `reg query HKCR\.leapgate`。通过：两个键都在，前者带 `URL Protocol` 值。
- [ ] 跑 `netsh advfirewall firewall show rule name="Leapgate Service"`。通过：有入站和出站各一条，程序路径是安装目录里的 `Leapgate.exe`。
- [ ] 看快捷方式。通过：开始菜单里有 Leapgate 文件夹，`%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Startup\` 下有 `Leapgate Tray.lnk`。
- [ ] 跑 `Get-CimInstance Win32_Process -Filter "Name='Leapgate.exe'" | Select-Object ProcessId, CommandLine`。通过：能看到带 `--service`、`--server`、`--tray` 的进程，以及界面进程。
- [ ] 跑 `[System.IO.Directory]::GetFiles('\\.\pipe\') | Select-String 'Leapgate'`。通过：有 `\\.\pipe\Leapgate\query` 开头的管道。
- [ ] 以管理员身份看服务配置目录。通过：里面有 `Leapgate.toml`、`Leapgate2.toml`，`log\server\` 下有服务日志。

## 5. 外呼

这一节要在原版 RustDesk 没装、或者原版的服务和程序都已退出时做，否则原版自己的检查更新会混进结果。

- [ ] 以管理员身份开 DNS 客户端日志并清缓存：`wevtutil sl Microsoft-Windows-DNS-Client/Operational /e:true`、`ipconfig /flushdns`。然后用安装版 Leapgate 正常操作 10 分钟：重启一次 Leapgate 服务，打开设置各页，打开登录框并登录，发起一次连接。别点关于页和安装页里的链接。
- [ ] 接上一条，跑 `Get-WinEvent -LogName Microsoft-Windows-DNS-Client/Operational | Where-Object Message -match 'rustdesk' | Select-Object TimeCreated, Message`。通过：没有任何 `rustdesk.com` 子域名的查询，包括 `rs-ny.rustdesk.com`、`api.rustdesk.com`、`admin.rustdesk.com`。
- [ ] 在同一段日志里找你的 leapgate-server 地址和 4 个第三方 STUN 服务器（`stun.cloudflare.com`、`stun.l.google.com`、`stun.antisip.com`、`stun.nextcloud.com`）。通过：能找到它们，这两类是预期的外呼；STUN 用来探测本机公网 IPv6，保留还是换掉待维护者决定。日志里也有其他程序的查询，看到疑似 Leapgate 发出的陌生域名就记下来。
- [ ] 在"设置 → 常规"里勾选 "Auto update"，以管理员身份 `sc stop Leapgate`、`sc start Leapgate`，等 2 分钟（上游在服务启动 30 秒后做第一次检查）。通过：DNS 日志里没有 `api.rustdesk.com`；服务日志里没有 "New version available" 和 "Error checking for updates"；`C:\ProgramData\RustDesk\RustDeskCustomClientStaging` 没有新建或改动。勾选框还在但不起作用，这是预期的。勾选保持打开，第 6 节还要用。

## 6. 与原版共存

- [ ] 在已装 Leapgate 的机器上安装原版 RustDesk，在它的"设置 → 网络"里填你的 leapgate-server 地址和公钥。通过：安装正常，原版的默认安装路径是 `C:\Program Files\RustDesk`，没有覆盖 Leapgate 的目录。
- [ ] 跑 `sc query Leapgate` 和 `sc query RustDesk`。通过：两个服务都是 RUNNING，托盘里各有一个图标，图标和名字各是各的。
- [ ] 对比两边主界面的 ID。通过：两个 ID 不同，两边状态都是就绪。
- [ ] 对比两边的配置目录和注册表：`%APPDATA%\Leapgate\config` 与 `%APPDATA%\RustDesk\config`，`Uninstall\Leapgate` 与 `Uninstall\RustDesk`，`HKCR\leapgate` 与 `HKCR\rustdesk`。通过：各自独立，内容互不混用。
- [ ] 在 Leapgate 里改一次固定密码。通过：原版的固定密码不变，原版用旧密码仍能被连接。
- [ ] 记下原版进程的 PID（`Get-Process RustDesk`），以管理员身份重启 Leapgate 服务。通过：原版进程的 PID 不变；如果原版正开着隐私模式、有 `RuntimeBroker_rustdesk.exe` 在跑，它也没有被结束（Leapgate 的服务启动时只结束 `RuntimeBroker_leapgate.exe`）。
- [ ] 让 Leapgate 带着第 5 节打开的 "Auto update" 再跑 2 分钟以上。通过：`C:\Program Files\RustDesk\RustDesk.exe` 的版本号和修改时间都没变。
- [ ] 原版装过远程打印机时，跑 `Get-Printer`。通过：原版的 "RustDesk Printer" 还在，能打印。
- [ ] 两边都卸掉，先装 Leapgate 再装原版，把本节前四条再走一遍。通过：结果和先装原版时一样。

## 7. 连接

两端都指向你的 leapgate-server。远程窗口标签上的连接图标，鼠标悬停会显示"加密直连"或"加密中继连接"，下文用它判断连接类型。

- [ ] 在同一台机器上，用 Leapgate 连接原版的 ID。通过：输入密码后能看到画面（画面会层层嵌套，属正常），能操作鼠标键盘。
- [ ] 在同一台机器上，用原版连接 Leapgate 的 ID。通过：同上。
- [ ] 在第二台机器上，用 Leapgate 和原版分别连主测试机上的 Leapgate 和原版，再反方向各连一次。通过：四个方向都能连上并操作。
- [ ] 在设备卡片的右键菜单里勾选"总是通过中继连接"后再连。通过：悬停提示是"加密中继连接"，画面和操作正常。
- [ ] 在 Leapgate 的"设置 → 常规"里看 "Enable IPv6 P2P connection"。通过：没有手动勾过它时也显示已勾选，用户配置目录里的 `Leapgate_local.toml` 没有 `enable-ipv6-punch` 这个键。
- [ ] 两台机器都有 IPv6、都没开"总是通过中继连接"时，用 Leapgate 连另一台。通过：悬停提示是"加密直连"，资源监视器"网络"页里 Leapgate.exe 的连接对端是 IPv6 地址；服务端 `leapgate-server stats` 里直连类结果的计数加一。
- [ ] 用原版做控制端，手动勾选它的 "Enable IPv6 P2P connection" 后连同一台被控端。通过：同样是"加密直连"。原版默认不勾这个选项，这条用来对照 Leapgate 默认打开的效果。
- [ ] 在 Leapgate 里用测试账号登录。通过：登录成功，界面显示用户名。
- [ ] 登录后再连一次任一设备。通过：能正常连上，不会在约 18 秒后失败（这验证 leapgate-server 的会合端口密钥交换）。
- [ ] 打开地址簿。通过：能看到"My address book"；把一台设备加进去，退出 Leapgate 再打开，设备还在。
- [ ] 在服务端用 `leapgate-server ab create <簿名> --owner <另一个用户>` 建共享簿，再 `leapgate-server ab grant <簿名> --user <测试账号> ro`。通过：Leapgate 里出现这本共享簿，只读权限下不能增删设备；改成 `rw` 后可以。
- [ ] 在服务端跑 `leapgate-server device list`。通过：列表里有 Leapgate 的 ID，主机名、账号、版本号正确。
- [ ] 在一次会话里打开文件传输，两个方向各传一个文件。通过：文件完整，大小一致。
- [ ] 建一条 TCP 端口转发（例如转发对端的 3389），用对应的客户端连本地端口。通过：能连通。

## 8. Flutter 3.44 回归

这一节是 `docs/research/第二期客户端/03-Windows构建链方案.md` §2.3 的第二、三道关；第一道关（多窗口压力）见第 10 节。任何一条不过，按笔记 03 的顺序考虑退回自编引擎（C）或 Flutter 3.24.5（A）。

- [ ] 被控端在"设置 → 常规 → Hardware Codec"里打开硬件编解码，分别用 H.264 和 H.265；控制端打开 "Use texture rendering"，1080p60 连续跑 10 分钟以上，期间拖动、缩放窗口。通过：不闪烁、不黑屏、不崩溃。
- [ ] 打开"添加到地址簿"对话框，在下拉框里输入文字过滤、选一项，再打开一次。通过：第二次打开时列出全部条目，不是上次过滤后的结果。
- [ ] 在亮色和暗色主题下各打开几个对话框（例如设置密码、添加到地址簿）。通过：对话框背景色正常，文字清楚。
- [ ] 在 Leapgate 的输入框（例如搜索框、地址簿备注）和远程会话里用中文输入法打字。通过：候选框位置正常，能上屏。
- [ ] 有两块缩放比例不同的显示器时，把 Leapgate 主窗口和会话窗口在两块屏之间来回拖。通过：界面按新屏的缩放比例正常显示，不模糊、不错位。

## 9. 卸载

- [ ] 从"设置 → 应用 → 已安装的应用"卸载 Leapgate。通过：卸载完成，没有报错。
- [ ] 卸载后跑 `sc query Leapgate`，查 `Uninstall\Leapgate`、`HKCR\leapgate`、`HKCR\.leapgate`、防火墙规则 `Leapgate Service`，看 `C:\Program Files\Leapgate`、开始菜单的 Leapgate 文件夹和 `Leapgate Tray.lnk`。通过：服务不存在，这些键、规则、目录和快捷方式都没了。用户配置目录和服务配置目录会保留（上游的卸载脚本不删配置），这是预期的。
- [ ] 卸载后看原版 RustDesk。通过：服务 RUNNING，ID 和配置没变，从第二台机器还能连上它。
- [ ] 原版用过虚拟显示时，卸载 Leapgate 后在原版上再插一次虚拟显示器。记录结果：按上游代码，Leapgate 卸载时会无条件卸掉两边共用的 Amyuni 虚拟显示驱动，原版下次使用时应当会自己重装，第一次会有延迟。
- [ ] 重新装回 Leapgate 并登录，再卸载原版。通过：Leapgate 的服务、ID、登录状态和地址簿都不受影响。

## 10. 本期不测和已知缺口

下面这些在本期构建里还没做，或者要等维护者决定。测到相关现象时记一笔即可，不算冒烟失败。

- 代码签名：前两期不签名。UAC 显示"未知发布者"，从网上下载的安装包会被 SmartScreen 拦一下，个别杀毒软件可能误报。签名方案在分发给别人之前再定。
- 多窗口压力测试（笔记 03 §2.3 第一道关）：反复开关会话窗口 50 次、把标签拖成独立窗口、文件传输和端口转发窗口反复开关、被控端连接管理窗口反复弹出关闭，同时看内存是否持续上涨。方案 B 用的官方 Flutter 引擎没有上游绕开多窗口崩溃（flutter#155685）的补丁，这一关要单独安排时间做，第二期验收前必须过。
- 虚拟显示驱动、打印机驱动、`WindowInjection.dll`：构建脚本还没打包这三样外部组件，所以本期测不了虚拟显示、远程打印，以及依赖 `WindowInjection.dll` 的隐私模式实现。上游已签名的驱动在不签名的 Leapgate 里能不能正常安装，也留到打包后再验证。
- 共用驱动的卸载保护：Leapgate 卸载时会卸掉 Amyuni 虚拟显示驱动，并尝试卸载两边同名的 "RustDesk v4 Printer Driver"。要不要在检测到原版还装着时跳过，待维护者决定，第 9 节只记录现象。
- 两个固定端口：局域网发现 UDP 21119 和直接 IP 访问 TCP 21118 两边会抢，后启动的一方监听失败。改名解决不了，暂不处理。
- 关于页的 Privacy Statement、Website 链接和安装页的最终用户许可协议链接仍指向 rustdesk.com；版本资源里的 CompanyName 和版权署名暂写 "Leapgate contributors"。都待维护者定。
- 第三方 STUN：客户端会向 4 个第三方 STUN 服务器探测本机公网 IPv6，和 IPv6 打洞开没开无关。保留、换成自建还是只用本机探测，待维护者定。
- "Auto update"勾选框：Leapgate 已关掉官方自动更新，勾选框仍显示但不起作用；去掉它要改上游 `flutter/`，留到新界面里不再做。
- `custom.txt`：Leapgate 现在仍会读 exe 旁边经 RustDesk 官方签名的 `custom.txt`，要不要用挂钩关掉待维护者定，本期不测。
- Flutter 产物里的本机路径：`data\app.so`、`flutter_gpu_texture_renderer_plugin.dll` 里还带着构建机的用户目录。第一次分发给别人之前，改在用户目录以外的目录构建来去掉。
- 旧版 Inno Setup 卸载键：Leapgate 已改为只认自己的注册表项，不再读旧版 RustDesk 的 `IS1` 键。要测得先装一个很老的、用 Inno Setup 安装的 RustDesk，本期不测。
- MSI 安装包和便携安装包 `leapgate-<版本>-install.exe`：本期不出 MSI；便携安装包可以用 `build.py` 不带 `--skip-portable-pack` 生成，但不在本清单里测。
- 其他平台：第一阶段只做 Windows。
